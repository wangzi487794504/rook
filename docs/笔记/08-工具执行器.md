# 08 — 工具执行器：并发 / 串行 / 权限

## 这一章做什么

实现 **ToolExecutor**—— 把模型返回的多个工具调用安全、高效地执行完。

**完成后你能做到：**

- AI 一次返回 5 个工具调用，只读的并发跑，写入的串行跑
- 既快又安全，不会因为并发写导致文件冲突
- 每个工具执行前自动检查权限，防止危险操作
- 结果按原始顺序返回，上层不用关心并发细节

## 为什么需要

### 问题 1：全串行太慢

AI 可能一次返回好几个工具调用：

```
工具1: read_file("a.java")
工具2: read_file("b.java")  
工具3: read_file("c.java")
工具4: read_file("d.java")
```

如果一个一个串行执行，每个 100ms，4 个就是 400ms。用户等很久。

### 问题 2：全并发不安全

但如果所有工具都并发跑，可能出问题：

```
工具1: write_file("config.yaml", xxx)
工具2: edit_file("config.yaml", yyy)
```

两个同时改同一个文件 → 文件内容乱了 → 数据损坏。

### 解决方案：分批执行

**只读工具并发跑，写入工具串行跑。**

- **只读工具**（read_file、glob、grep）：不会修改任何东西，并发跑没问题，越快越好
- **写入工具**（write_file、edit_file、exec_command）：可能修改文件或系统，一个一个来，安全第一

## 核心概念

### 保序分批

扫描工具调用列表，把连续的只读工具合并成一个 "并发批"，遇到写入工具就单独串行执行。

**"保序" 是什么意思？**

结果的顺序和输入的顺序一致。虽然并发执行了，但返回给上层的时候，还是按原来的顺序排好。

### ExecutorService

Java 的线程池，用来并发执行任务。

**为什么用线程池不用直接 new Thread？**

- 线程池复用线程，不用每次都创建销毁
- 可以控制最大并发数，防止线程太多
- 有 invokeAll 等便捷方法

### 权限注入

每个工具执行前，先过一遍权限检查引擎，判断能不能执行。

**检查什么？**

- 是不是高危命令？
- 路径是不是越界了？
- 是不是在黑名单里？
- 需要用户确认吗？

## 完整代码详解

```java
// tools/ToolExecutor.java
package com.rook.tools;

import com.rook.permission.PermissionEngine;
import com.rook.permission.PermissionResult;

import java.util.*;
import java.util.concurrent.*;

public class ToolExecutor {

    // 只读工具集合（不会修改文件系统，可以并发）
    private static final Set<String> READ_ONLY = Set.of("read_file", "glob", "grep");

    private final ToolRegistry registry;
    private final int maxParallelReads;
    private final PermissionEngine permissionEngine;

    public ToolExecutor(ToolRegistry registry, int maxParallelReads,
                        PermissionEngine permissionEngine) {
        this.registry = registry;
        this.maxParallelReads = maxParallelReads;
        this.permissionEngine = permissionEngine;
    }

    /**
     * 保序分批并发执行
     * - 连续的只读工具 → 合并为一批，并发执行
     * - 写入/命令工具 → 单独串行执行
     * - 结果按原始顺序返回
     */
    public List<ToolResult> execute(List<ToolCall> calls) {
        if (calls == null || calls.isEmpty()) {
            return List.of();
        }

        // 用 ConcurrentHashMap 存结果，key 是原始索引
        Map<Integer, ToolResult> resultMap = new ConcurrentHashMap<>();
        
        // 创建线程池
        ExecutorService executor = Executors.newFixedThreadPool(maxParallelReads);

        try {
            int i = 0;
            while (i < calls.size()) {
                ToolCall call = calls.get(i);

                if (READ_ONLY.contains(call.name())) {
                    // ★ 情况 1：只读工具 → 收集连续的，组成并发批
                    List<Integer> batchIndices = new ArrayList<>();
                    List<Callable<Void>> batch = new ArrayList<>();
                    
                    while (i < calls.size() && READ_ONLY.contains(calls.get(i).name())) {
                        int idx = i;  // 捕获当前索引
                        batchIndices.add(idx);
                        batch.add(() -> {
                            resultMap.put(idx, executeOne(calls.get(idx)));
                            return null;
                        });
                        i++;
                    }
                    
                    // 并发执行整批，等待全部完成
                    executor.invokeAll(batch);
                    
                } else {
                    // ★ 情况 2：写入/命令工具 → 单独串行执行
                    resultMap.put(i, executeOne(call));
                    i++;
                }
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            executor.shutdownNow();
        }

        // 按原始顺序排列结果
        List<ToolResult> results = new ArrayList<>();
        for (int j = 0; j < calls.size(); j++) {
            results.add(resultMap.getOrDefault(j, ToolResult.error("未执行")));
        }
        return results;
    }

    /**
     * 执行单个工具（权限检查前置）
     */
    private ToolResult executeOne(ToolCall call) {
        // 1. 查找工具
        Optional<Tool> tool = registry.get(call.name());
        if (tool.isEmpty()) {
            return ToolResult.error("未知工具: " + call.name());
        }

        // 2. ★ 权限检查
        PermissionResult perm = permissionEngine.check(call, null);
        if (perm.isDenied()) {
            return ToolResult.error("PERMISSION_DENIED: " + perm.reason());
        }

        // 3. 执行工具
        try {
            return tool.get().execute(call.input());
        } catch (Exception e) {
            // 捕获所有异常，不让单个工具失败影响整批
            return ToolResult.error("执行异常: " + e.getMessage());
        }
    }
}
```

## 逐段详解

### 1. 只读工具集合

```java
private static final Set<String> READ_ONLY = Set.of("read_file", "glob", "grep");
```

**哪些工具是只读的？**

- `read_file` — 读文件，不会修改
- `glob` — 搜索文件名，不会修改
- `grep` — 搜索文件内容，不会修改

**这些工具可以安全并发执行，不会互相干扰。**

**哪些是写入的？**

- `write_file` — 写文件，会修改
- `edit_file` — 改文件，会修改
- `exec_command` — 执行命令，可能修改任何东西

**写入工具必须串行，一个一个来。**

### 2. 构造器

```java
public ToolExecutor(ToolRegistry registry, int maxParallelReads,
                    PermissionEngine permissionEngine) {
    this.registry = registry;
    this.maxParallelReads = maxParallelReads;
    this.permissionEngine = permissionEngine;
}
```

**三个参数：**

- `registry` — 工具注册中心，用来查找工具
- `maxParallelReads` — 最大并发数（比如 3，就是同时最多跑 3 个只读工具）
- `permissionEngine` — 权限引擎，执行前检查

### 3. execute () 主方法

```
public List<ToolResult> execute(List<ToolCall> calls) {
```

**输入：** 工具调用列表（LLM 返回的）

**输出：** 工具结果列表（顺序和输入一致）

#### 3.1 空输入处理

```
if (calls == null || calls.isEmpty()) {
    return List.of();
}
```

空列表直接返回，不用往下走。

#### 3.2 结果存储

```
Map<Integer, ToolResult> resultMap = new ConcurrentHashMap<>();
```

**用 ConcurrentHashMap 存结果，key 是原始索引。**

**为什么用 Map 不是 List？**

- 并发执行时，任务完成顺序不确定
- 用 index 做 key，不管哪个先完成，都放到正确的位置
- 最后按 index 排序，就得到原始顺序

**为什么用 ConcurrentHashMap？**

- 多个线程同时写
- 普通 HashMap 并发写会出问题（死循环、数据丢失）
- ConcurrentHashMap 是线程安全的

#### 3.3 创建线程池

```
ExecutorService executor = Executors.newFixedThreadPool(maxParallelReads);
```

创建固定大小的线程池。

**`newFixedThreadPool(3)` 是什么意思？**

- 池子里有 3 个线程
- 最多同时跑 3 个任务
- 第 4 个任务来了就排队等

**为什么要限制并发数？**

- 防止线程太多把系统搞崩
- 防止请求太多被 API 限流
- 一般 3-5 个就够了

#### 3.4 主循环：保序分批

```java
int i = 0;
while (i < calls.size()) {
    ToolCall call = calls.get(i);

    if (READ_ONLY.contains(call.name())) {
        // 只读 → 收集连续的，组成并发批
        ...
    } else {
        // 写入 → 单独串行
        ...
    }
}
```

**核心算法：扫描 + 分批**

从前往后扫，遇到只读的就攒起来，攒够一批就并发跑；遇到写入的就立刻串行执行。

##### 情况 A：只读工具 → 组成并发批

```java
if (READ_ONLY.contains(call.name())) {
    List<Integer> batchIndices = new ArrayList<>();
    List<Callable<Void>> batch = new ArrayList<>();
    
    while (i < calls.size() && READ_ONLY.contains(calls.get(i).name())) {
        int idx = i;  // 捕获当前索引
        batchIndices.add(idx);
        batch.add(() -> {
            resultMap.put(idx, executeOne(calls.get(idx)));
            return null;
        });
        i++;
    }
    executor.invokeAll(batch);  // 并发执行整批
}
```

**这段做了什么？**

1. 发现当前是只读工具
2. 继续往后找，把连续的只读工具都收集起来
3. 收集成一个 "批"
4. 把整批提交给线程池并发执行
5. 等待整批都完成

**为什么要收集连续的？**

- 保证顺序
- 比如 [read, read, write, read] 要分成三批：[read, read] 并发 → [write] 串行 → [read] 并发
- 不能把最后那个 read 和前面两个放一起，因为中间隔了个 write

**`int idx = i;` 为什么要单独定义？**

Lambda 表达式里引用外部变量，要求变量是 final 或 effectively final。

循环变量 i 在变，所以要在每次循环里捕获当前的值到 idx 里。

**`invokeAll(batch)` 做了什么？**

- 提交所有任务
- 阻塞等待，直到所有任务都完成
- 全部完成后才往下走

##### 情况 B：写入工具 → 串行执行

```
} else {
    resultMap.put(i, executeOne(call));
    i++;
}
```

写入工具直接在当前线程执行，一个一个来。

**为什么写入工具要串行？**

- 防止两个写入工具同时改同一个文件
- 防止命令执行互相影响
- 安全第一，慢点没关系

#### 3.5 异常处理

```
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
} finally {
    executor.shutdownNow();
}
```

**InterruptedException：**

- 线程在等待时被中断了
- 恢复中断标记，让上层知道

**finally 里关闭线程池：**

- 不管正常还是异常，都要关闭线程池
- `shutdownNow()` 立刻关闭，正在跑的任务也会被中断

#### 3.6 按原始顺序排列结果

```
List<ToolResult> results = new ArrayList<>();
for (int j = 0; j < calls.size(); j++) {
    results.add(resultMap.getOrDefault(j, ToolResult.error("未执行")));
}
return results;
```

**从 0 到 n-1 按索引取结果，组成列表。**

**为什么要这一步？**

- 并发执行时，任务完成顺序不确定
- 但 resultMap 里按 index 存了
- 按 index 顺序取出来，就和输入顺序一致了

**`getOrDefault(j, ...)` 是什么？**

- 如果某个 index 没有结果（比如异常了没执行到）
- 就返回一个默认的错误结果
- 保证结果列表的长度和输入一样

### 4. executeOne () — 执行单个工具

```java
private ToolResult executeOne(ToolCall call) {
    // 1. 查找工具
    Optional<Tool> tool = registry.get(call.name());
    if (tool.isEmpty()) {
        return ToolResult.error("未知工具: " + call.name());
    }

    // 2. ★ 权限检查
    PermissionResult perm = permissionEngine.check(call, null);
    if (perm.isDenied()) {
        return ToolResult.error("PERMISSION_DENIED: " + perm.reason());
    }

    // 3. 执行工具
    try {
        return tool.get().execute(call.input());
    } catch (Exception e) {
        return ToolResult.error("执行异常: " + e.getMessage());
    }
}
```

**三步：找工具 → 查权限 → 执行**

#### 4.1 查找工具

```java
Optional<Tool> tool = registry.get(call.name());
if (tool.isEmpty()) {
    return ToolResult.error("未知工具: " + call.name());
}
```

从注册中心找工具，找不到就返回错误。

#### 4.2 权限检查（核心）

```java
PermissionResult perm = permissionEngine.check(call, null);
if (perm.isDenied()) {
    return ToolResult.error("PERMISSION_DENIED: " + perm.reason());
}
```

**执行前先检查权限，通不过就直接拒绝。**

**为什么权限检查放在这里？**

- 统一入口，所有工具都要过
- 不用在每个工具里重复写权限逻辑
- 权限策略可以独立演化

#### 4.3 执行工具

```java
try {
    return tool.get().execute(call.input());
} catch (Exception e) {
    return ToolResult.error("执行异常: " + e.getMessage());
}
```

**捕获所有异常。**

**为什么要 catch Exception？**

- 单个工具失败，不应该影响整批
- 捕获住，返回错误结果
- 其他工具继续执行

### 示例 1：混合调用

**输入：**

```
[read_file, glob, edit_file, grep, grep, write_file, read_file]
```

**分批过程：**

```
扫描位置 0: read_file（只读）→ 开始收集批1
扫描位置 1: glob（只读）→ 加入批1
扫描位置 2: edit_file（写入）→ 批1收集结束，并发执行批1
                        → 遇到写入，单独串行执行
扫描位置 3: grep（只读）→ 开始收集批2
扫描位置 4: grep（只读）→ 加入批2
扫描位置 5: write_file（写入）→ 批2收集结束，并发执行批2
                          → 遇到写入，单独串行执行
扫描位置 6: read_file（只读）→ 开始收集批3
扫描结束 → 批3收集结束，并发执行批3
```

**时间线：**

```
时间轴 →

[read_file] ──┐
[glob]     ──┘  并发，假设共 100ms

[edit_file] ────  串行，50ms

[grep] ──┐
[grep] ──┘  并发，80ms

[write_file] ───  串行，60ms

[read_file] ───  并发（只有1个），30ms

总耗时：100 + 50 + 80 + 60 + 30 = 320ms

如果全串行：100 + 50 + 80 + 60 + 30 = 320ms？不对...
（假设每个工具单独跑的时间）

重新算：
read_file: 50ms
glob: 50ms
→ 并发跑：50ms（不是 100ms）

edit_file: 50ms

grep: 40ms
grep: 40ms
→ 并发跑：40ms

write_file: 60ms

read_file: 30ms

总耗时：50 + 50 + 40 + 60 + 30 = 230ms

如果全串行：50+50+50+40+40+60+30 = 320ms

节省了 90ms，约 28%
```

**结果顺序：**

```
[结果0, 结果1, 结果2, 结果3, 结果4, 结果5, 结果6]
↑ 和输入顺序完全一致
```

## 权限注入详解

```
executeOne(call)
    │
    ▼
PermissionEngine.check(call, lineReader)
    │
    ├─ 1. Blacklist.check()        — 高危命令拦截
    │     比如 rm -rf /、format c:
    │
    ├─ 2. PathSandbox.check()      — 路径逃逸检测
    │     比如 ../../etc/passwd
    │
    ├─ 3. RuleEngine.check()       — YAML 规则匹配
    │     自定义规则：哪些允许、哪些拒绝
    │
    ├─ 4. PermissionMode.verdict() — 模式兜底
    │     - 全允许模式：都放行
    │     - 全拒绝模式：都拦住
    │     - 白名单模式：只允许白名单里的
    │
    └─ 5. HumanInTheLoop.ask()     — 用户确认
          不确定的话，问用户同不同意
    │
    ▼
Tool.execute(params)
```

### 每层检查的作用

#### 1. 黑名单（最基础）

直接拦截已知的危险操作：

- `rm -rf /`
- `mkfs` 格式化
- 访问系统敏感目录

#### 2. 路径沙箱

确保操作的文件在允许的目录内：

- 只能操作当前项目目录
- 不能用 `../../` 逃出去
- 不能访问系统文件

#### 3. 规则引擎

用户可以自己写规则：

```yaml
rules:
  - allow: "read_file"
    path: "src/**"
    
  - deny: "exec_command"
    pattern: "rm .*"
```

#### 4. 权限模式

全局开关：

- **宽松模式**：都允许，只拦最危险的
- **正常模式**：按规则来
- **严格模式**：默认拒绝，只放行白名单
- **确认模式**：每个操作都要用户确认

#### 5. 人工确认

拿不准的，问用户：

```
AI 想执行命令: rm -rf ./target
允许吗？(y/N)
```

## 常见坑（详细版）

### 1. HashMap 并发写入

**现象：** 偶发的诡异 bug，结果丢失、死循环、CPU 100%。

**原因：** 用了普通 HashMap，多个线程同时 put。

**HashMap 并发写的问题：**

- JDK 7 之前可能死循环（链表成环）
- JDK 8 之后不会死循环，但可能数据丢失
- 总之就是线程不安全

**解决：** 用 `ConcurrentHashMap`。

```java
// 错误
Map<Integer, ToolResult> resultMap = new HashMap<>();

// 正确
Map<Integer, ToolResult> resultMap = new ConcurrentHashMap<>();
```

### 2. 结果顺序错乱

**现象：** 并发执行后，结果顺序和输入对不上。

**原因：** 直接按完成顺序 append 到列表里。

```java
// 错误：谁先完成谁在前，顺序乱了
List<ToolResult> results = new ArrayList<>();
batch.add(() -> {
    results.add(executeOne(call));  // 直接 add，顺序不对
    return null;
});
```

**正确做法：** 用 index 做 key 存到 Map，最后按 index 排序。

```
// 正确：按 index 存，最后按 index 取
resultMap.put(idx, executeOne(calls.get(idx)));
...
for (int j = 0; j < calls.size(); j++) {
    results.add(resultMap.get(j));
}
```

### 3. 权限检查失败不中断

**现象：** 一个工具权限不通过，整批都停了。

**正确做法：** 单个工具权限失败，只影响它自己，返回错误结果，其他工具继续执行。

**为什么？**

- AI 可能一次调用 5 个工具，其中 1 个没权限
- 不能因为 1 个失败，其他 4 个都不跑了
- 返回 PERMISSION_DENIED，让 AI 自己调整

### 4. 线程池没关闭

**现象：** 程序退出了但进程还在，或者线程泄漏。

**原因：** 线程池用完没 shutdown。

**正确做法：** 用 try-finally，确保一定关闭。

```java
ExecutorService executor = Executors.newFixedThreadPool(n);
try {
    // 使用线程池
} finally {
    executor.shutdownNow();  // 一定关闭
}
```

### 5. 写入工具也并发了

**现象：** 文件内容乱了，或者出现奇怪的错误。

**原因：** 分批逻辑写错了，把写入工具也放到并发批里了。

**检查：**

- READ_ONLY 集合里是不是误加了写入工具？
- 分批的 while 条件是不是正确？
- 写入工具是不是走的串行分支？

### 6. invokeAll 不响应中断

**现象：** 调用 interrupt ()，但 invokeAll 还在等。

**原因：** invokeAll 会等待所有任务完成，中断后会取消任务，但还是会等所有任务响应取消。

**解决：**

- 任务本身要支持中断（检查 Thread.interrupted ()）
- 或者用 invokeAll 带超时的版本
