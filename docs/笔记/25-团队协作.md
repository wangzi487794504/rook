# 25 — 团队协作

## 这一章做什么

创建**长期团队**，Lead 拆解任务写到共享清单，派多个队员并行干活。队员间点对点发消息，Coordinator 模式让 Lead 只做决策不动手。

**完成后你能做到：**

- `/team create myteam` → 创建一个持久化的团队
- Lead 把大任务拆成小任务，写到共享 TaskBoard
- 派 Alice 做代码审查，Bob 跑测试，Charlie 改 bug → 并行
- Alice 给 Bob 发消息："pom.xml 有问题" → Bob 下一轮看到
- Coordinator 模式：Lead 只做决策和管理，不能直接改文件

## 为什么需要

### 单个子 Agent 的局限

```
单个子 Agent：
  一次只能做一件事
  审查完代码才能跑测试
  跑完测试才能改 bug
  串行，慢
```

### 团队协作的优势

```
Team:
  Lead 拆解任务
    ├─ Alice (review)  → 审查代码 ──┐
    ├─ Bob (test)      → 跑测试   ──┼─ 并行
    └─ Charlie (fix)   → 改 bug   ──┘
  队员间发消息协作
  Lead 汇总结果
```

**好处：**

- 并行：多个队员同时干活，快
- 专业：每个队员有专门的角色和工具
- 解耦：任务拆成小颗粒，各自独立
- 协作：队员间可以发消息、同步状态
- 持久化：团队配置存盘，重启不丢

## 核心概念

### Team（团队）

- name + lead + members + config.json 持久化
- 长期存在，不是一次性的
- 成员可以增删，状态可以恢复

### TaskBoard（共享任务清单）

- 共享的任务列表，所有队员都能读写
- 每条任务带状态（todo/in-progress/done/blocked）
- 依赖字段：blocks /blockedBy，任务间有依赖关系
- Lead 拆解任务，队员认领执行

### Mailbox（消息邮箱）

- 队员间点对点发消息
- 锁文件保证并发安全
- 3 种消息：text（普通）、shutdown（停止）、plan_approval（计划审批）
- 未读消息在下一轮 Agent Loop 以 system reminder 形式提醒

### Coordinator Mode（协调者模式）

- 两把锁：feature flag + 环境变量，同时开启才生效
- Lead 只能读 + 团队管理，不能 writeFile/editFile
- Lead 只做决策、拆解任务、派队员，不亲自动手
- 防止 Lead 既当裁判又当运动员

## 第一步：Team — 团队数据结构

```
// team/Team.java
package com.rook.team;

import com.fasterxml.jackson.databind.ObjectMapper;
import java.io.IOException;
import java.nio.file.*;
import java.util.*;

public class Team {

    private static final ObjectMapper MAPPER = new ObjectMapper();

    private String name;
    private String leadId;
    private List<Member> members;
    private Path baseDir;  // .rook/teams/<name>/

    public Team(String name, String leadId) {
        this.name = name;
        this.leadId = leadId;
        this.members = new ArrayList<>();
        this.baseDir = Paths.get(".rook/teams").resolve(name);
    }

    // ── 成员管理 ──

    public void addMember(Member member) {
        members.add(member);
    }

    public void removeMember(String memberId) {
        members.removeIf(m -> m.id().equals(memberId));
    }

    public Optional<Member> findMember(String memberId) {
        return members.stream()
            .filter(m -> m.id().equals(memberId))
            .findFirst();
    }

    public List<Member> getMembers() {
        return Collections.unmodifiableList(members);
    }

    // ── 持久化 ──

    public void save() throws IOException {
        Files.createDirectories(baseDir);
        Path configFile = baseDir.resolve("config.json");
        MAPPER.writerWithDefaultPrettyPrinter()
            .writeValue(configFile.toFile(), this);
    }

    public static Team load(Path teamDir) throws IOException {
        Path configFile = teamDir.resolve("config.json");
        Team team = MAPPER.readValue(configFile.toFile(), Team.class);
        team.baseDir = teamDir;
        return team;
    }

    // ── getter ──
    public String name() { return name; }
    public String leadId() { return leadId; }
    public Path baseDir() { return baseDir; }
}

// ── 成员 ──
public record Member(
    String name,        // 显示名，如 "Alice"
    String id,          // 唯一标识，如 "alice-001"
    String role,        // 角色：lead/reviewer/tester/developer
    String agentType,   // 对应的子 Agent 类型，如 "review"
    String status,      // 状态：idle/in-progress/blocked/done/stopped
    boolean worktreeIsolated  // 是否用 worktree 隔离
) {}
```

### 逐段详解

#### 1. 持久化结构

```
.rook/teams/myteam/
├── config.json          ← 团队配置（成员、角色等）
├── tasks.json           ← 任务清单（TaskBoard）
├── mailbox/             ← 消息目录
│   ├── alice/           ← Alice 的收件箱
│   │   ├── 001.json
│   │   └── 002.json
│   └── bob/
└── worktrees/           ← 队员的 worktree（可选）
```

**每个团队一个目录，所有数据都在里面。**

- config.json：团队和成员信息
- tasks.json：共享任务清单
- mailbox/：每个人的收件箱
- 重启后加载这个目录，团队就恢复了

|       字段       |       含义        |                 示例                  |

## 第二步：TeamManager — 团队管理

```
// team/TeamManager.java
package com.rook.team;

import java.io.IOException;
import java.nio.file.*;
import java.util.*;

public class TeamManager {

    private final Path teamsDir;

    public TeamManager() {
        this.teamsDir = Paths.get(".rook/teams");
    }

    /**
     * 创建团队
     */
    public Team create(String name, String leadId) throws IOException {
        // 校验团队名
        if (!name.matches("[a-zA-Z0-9_-]+")) {
            throw new IllegalArgumentException("团队名只能包含字母、数字、下划线、连字符");
        }

        Path teamDir = teamsDir.resolve(name);
        if (Files.exists(teamDir)) {
            throw new IllegalArgumentException("团队已存在: " + name);
        }

        Team team = new Team(name, leadId);
        team.addMember(new Member(
            "Lead", leadId, "lead", 
            null, "in-process", false
        ));
        team.save();

        System.out.println("[Team] 已创建团队: " + name);
        return team;
    }

    /**
     * 加载团队
     */
    public Team load(String name) throws IOException {
        Path teamDir = teamsDir.resolve(name);
        if (!Files.exists(teamDir)) {
            throw new IllegalArgumentException("团队不存在: " + name);
        }
        return Team.load(teamDir);
    }

    /**
     * 列出所有团队
     */
    public List<String> list() throws IOException {
        if (!Files.exists(teamsDir)) return List.of();

        List<String> teams = new ArrayList<>();
        try (DirectoryStream<Path> stream = Files.newDirectoryStream(teamsDir)) {
            for (Path entry : stream) {
                if (Files.isDirectory(entry) 
                        && Files.exists(entry.resolve("config.json"))) {
                    teams.add(entry.getFileName().toString());
                }
            }
        }
        return teams;
    }

    /**
     * 删除团队
     */
    public void delete(String name) throws IOException {
        Path teamDir = teamsDir.resolve(name);
        if (!Files.exists(teamDir)) return;

        // 递归删除（谨慎操作）
        deleteRecursively(teamDir);
        System.out.println("[Team] 已删除团队: " + name);
    }

    private void deleteRecursively(Path dir) throws IOException {
        if (!Files.exists(dir)) return;
        try (DirectoryStream<Path> stream = Files.newDirectoryStream(dir)) {
            for (Path entry : stream) {
                if (Files.isDirectory(entry)) {
                    deleteRecursively(entry);
                } else {
                    Files.delete(entry);
                }
            }
        }
        Files.delete(dir);
    }
}
```

## 第三步：TaskBoard — 共享任务清单

### Task 数据结构

```
// team/Task.java
package com.rook.team;

import java.util.List;

public record Task(
    String id,              // 任务 ID，如 "T-001"
    String title,           // 标题
    String description,     // 详细描述
    String status,          // todo/in-progress/done/blocked
    String assignee,        // 指派给谁（成员 id）
    List<String> blocks,    // 这个任务阻塞了哪些任务
    List<String> blockedBy, // 这个任务被哪些任务阻塞
    String result           // 完成结果（队员填写）
) {
    public Task withStatus(String newStatus) {
        return new Task(id, title, description, newStatus, assignee, 
            blocks, blockedBy, result);
    }

    public Task withResult(String newResult) {
        return new Task(id, title, description, status, assignee, 
            blocks, blockedBy, newResult);
    }
}
```

### TaskBoard 实现

```
// team/TaskBoard.java
package com.rook.team;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.SerializationFeature;
import java.io.IOException;
import java.nio.file.*;
import java.util.*;
import java.util.concurrent.atomic.AtomicInteger;

public class TaskBoard {

    private static final ObjectMapper MAPPER = new ObjectMapper()
        .enable(SerializationFeature.INDENT_OUTPUT);

    private final Path tasksFile;
    private final Path lockFile;
    private List<Task> tasks;
    private AtomicInteger idCounter;

    public TaskBoard(Path teamDir) {
        this.tasksFile = teamDir.resolve("tasks.json");
        this.lockFile = teamDir.resolve("tasks.lock");
        this.tasks = new ArrayList<>();
        this.idCounter = new AtomicInteger(0);
    }

    /**
     * 加载任务清单
     */
    public void load() throws IOException {
        if (!Files.exists(tasksFile)) {
            tasks = new ArrayList<>();
            idCounter.set(0);
            return;
        }
        tasks = new ArrayList<>(List.of(
            MAPPER.readValue(tasksFile.toFile(), Task[].class)
        ));
        // 计算下一个 ID
        int maxId = tasks.stream()
            .map(t -> t.id().replace("T-", ""))
            .filter(s -> s.matches("\\d+"))
            .mapToInt(Integer::parseInt)
            .max()
            .orElse(0);
        idCounter.set(maxId);
    }

    /**
     * 创建任务
     */
    public Task create(String title, String description) throws IOException {
        return withLock(() -> {
            String id = "T-" + String.format("%03d", idCounter.incrementAndGet());
            Task task = new Task(
                id, title, description, "todo", 
                null, List.of(), List.of(), null
            );
            tasks.add(task);
            save();
            return task;
        });
    }

    /**
     * 更新任务
     */
    public Task update(Task task) throws IOException {
        return withLock(() -> {
            int idx = -1;
            for (int i = 0; i < tasks.size(); i++) {
                if (tasks.get(i).id().equals(task.id())) {
                    idx = i;
                    break;
                }
            }
            if (idx < 0) {
                throw new IllegalArgumentException("任务不存在: " + task.id());
            }
            tasks.set(idx, task);
            save();
            return task;
        });
    }

    /**
     * 指派任务
     */
    public Task assign(String taskId, String assignee) throws IOException {
        Task task = find(taskId);
        Task updated = new Task(
            task.id(), task.title(), task.description(),
            "in-progress", assignee,
            task.blocks(), task.blockedBy(), task.result()
        );
        return update(updated);
    }

    /**
     * 完成任务
     */
    public Task complete(String taskId, String result) throws IOException {
        Task task = find(taskId);
        Task updated = new Task(
            task.id(), task.title(), task.description(),
            "done", task.assignee(),
            task.blocks(), task.blockedBy(), result
        );
        return update(updated);
    }

    /**
     * 查找任务
     */
    public Task find(String taskId) {
        return tasks.stream()
            .filter(t -> t.id().equals(taskId))
            .findFirst()
            .orElseThrow(() -> new IllegalArgumentException("任务不存在: " + taskId));
    }

    /**
     * 获取所有任务
     */
    public List<Task> all() {
        return Collections.unmodifiableList(tasks);
    }

    /**
     * 获取可认领的任务（todo 且未被阻塞）
     */
    public List<Task> available() {
        Set<String> blockedIds = new HashSet<>();
        for (Task t : tasks) {
            if (!"done".equals(t.status())) {
                blockedIds.addAll(t.blockedBy());
            }
        }
        return tasks.stream()
            .filter(t -> "todo".equals(t.status()))
            .filter(t -> !blockedIds.contains(t.id()))
            .toList();
    }

    // ── 锁机制 ──

    private <T> T withLock(LockedAction<T> action) throws IOException {
        // 自旋获取锁
        while (true) {
            try {
                Files.createFile(lockFile);  // O_CREATE|O_EXCL 原子创建
                try {
                    return action.execute();
                } finally {
                    Files.deleteIfExists(lockFile);
                }
            } catch (FileAlreadyExistsException e) {
                // 锁被占用，随机抖动后重试
                try {
                    Thread.sleep((long) (Math.random() * 100) + 50);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw new IOException("获取锁被中断", ie);
                }
            }
        }
    }

    private interface LockedAction<T> {
        T execute() throws IOException;
    }

    private void save() throws IOException {
        MAPPER.writeValue(tasksFile.toFile(), tasks);
    }
}
```

### 逐段详解

#### 1. 任务依赖

```
List<String> blocks,    // 这个任务阻塞了哪些任务
List<String> blockedBy  // 这个任务被哪些任务阻塞
```

**双向依赖关系：**

- A.blocks = [B] → A 完成后 B 才能开始
- B.blockedBy = [A] → B 被 A 阻塞

**示例：**

```
T-001: 审查代码
T-002: 修复审查发现的问题  blockedBy: [T-001]
T-003: 跑测试             blockedBy: [T-002]
```

- T-001 先做
- T-001 完成后 T-002 才能开始
- T-002 完成后 T-003 才能开始

#### 2. available () — 可认领任务

```
public List<Task> available() {
    Set<String> blockedIds = new HashSet<>();
    for (Task t : tasks) {
        if (!"done".equals(t.status())) {
            blockedIds.addAll(t.blockedBy());
        }
    }
    return tasks.stream()
        .filter(t -> "todo".equals(t.status()))
        .filter(t -> !blockedIds.contains(t.id()))
        .toList();
}
```

**逻辑：**

- 找出所有被未完成任务阻塞的任务 ID
- 状态是 todo 且不在阻塞列表里的，就是可认领的

**队员调用 available () 就能知道现在能做什么。**

#### 3. 锁文件并发安全

```
private <T> T withLock(LockedAction<T> action) {
    while (true) {
        try {
            Files.createFile(lockFile);  // 原子创建
            try {
                return action.execute();
            } finally {
                Files.deleteIfExists(lockFile);
            }
        } catch (FileAlreadyExistsException e) {
            Thread.sleep((long) (Math.random() * 100) + 50);  // 随机抖动
        }
    }
}
```

**★ 多个队员同时读写 TaskBoard，必须加锁。**

**原理：**

- `Files.createFile()` 是原子操作（O_CREATE | O_EXCL）
- 文件不存在则创建成功，获取锁
- 文件已存在则抛 FileAlreadyExistsException，没抢到锁
- 没抢到锁的，随机等待 50-150ms 后重试（随机抖动防止惊群）
- 执行完在 finally 里删除锁文件

**为什么不用 synchronized？**

- 多个子 Agent 是不同的进程，synchronized 只在同一个 JVM 里有效
- 锁文件是跨进程的，所有进程都能看到

## 第四步：Mailbox — 消息系统

### Message 数据结构

package com.rook.team;

public record Message(
    String id,          // 消息 ID
    String from,        // 发送者
    String to,          // 接收者
    String type,        // text / shutdown / plan_approval
    String subject,     // 主题
    String content,     // 内容
    long timestamp,     // 时间戳
    boolean read        // 是否已读

### Mailbox 实现

```
// team/Mailbox.java
package com.rook.team;

import com.fasterxml.jackson.databind.ObjectMapper;
import java.io.IOException;
import java.nio.file.*;
import java.util.*;
import java.util.concurrent.atomic.AtomicInteger;

public class Mailbox {

    private static final ObjectMapper MAPPER = new ObjectMapper();

    private final Path mailboxDir;
    private final Path lockFile;
    private final AtomicInteger msgCounter;

    public Mailbox(Path teamDir) {
        this.mailboxDir = teamDir.resolve("mailbox");
        this.lockFile = teamDir.resolve("mailbox.lock");
        this.msgCounter = new AtomicInteger(0);
    }

    /**
     * 发送消息
     */
    public void send(String from, String to, String content, 
                     String type, String subject) throws IOException {
        withLock(() -> {
            Path recipientDir = mailboxDir.resolve(to);
            Files.createDirectories(recipientDir);

            String msgId = "MSG-" + System.currentTimeMillis() + "-" 
                + msgCounter.incrementAndGet();
            Message msg = new Message(
                msgId, from, to, type, subject, content,
                System.currentTimeMillis(), false
            );

            Path msgFile = recipientDir.resolve(msgId + ".json");
            MAPPER.writerWithDefaultPrettyPrinter()
                .writeValue(msgFile.toFile(), msg);
            return null;
        });
    }

    /**
     * 读取未读消息（标记为已读）
     */
    public List<Message> readUnread(String memberId) throws IOException {
        return withLock(() -> {
            Path memberDir = mailboxDir.resolve(memberId);
            if (!Files.exists(memberDir)) return List.of();

            List<Message> unread = new ArrayList<>();
            try (DirectoryStream<Path> stream = 
                    Files.newDirectoryStream(memberDir, "*.json")) {
                for (Path msgFile : stream) {
                    Message msg = MAPPER.readValue(msgFile.toFile(), Message.class);
                    if (!msg.read()) {
                        unread.add(msg);
                        // 标记为已读
                        Message readMsg = new Message(
                            msg.id(), msg.from(), msg.to(), msg.type(),
                            msg.subject(), msg.content(), msg.timestamp(), true
                        );
                        MAPPER.writeValue(msgFile.toFile(), readMsg);
                    }
                }
            }
            // 按时间排序
            unread.sort(Comparator.comparingLong(Message::timestamp));
            return unread;
        });
    }

    /**
     * 获取未读消息数量
     */
    public int unreadCount(String memberId) throws IOException {
        Path memberDir = mailboxDir.resolve(memberId);
        if (!Files.exists(memberDir)) return 0;

        int count = 0;
        try (DirectoryStream<Path> stream = 
                Files.newDirectoryStream(memberDir, "*.json")) {
            for (Path msgFile : stream) {
                Message msg = MAPPER.readValue(msgFile.toFile(), Message.class);
                if (!msg.read()) count++;
            }
        }
        return count;
    }

    // ── 锁机制（和 TaskBoard 一样）──
    private <T> T withLock(LockedAction<T> action) throws IOException {
        while (true) {
            try {
                Files.createFile(lockFile);
                try {
                    return action.execute();
                } finally {
                    Files.deleteIfExists(lockFile);
                }
            } catch (FileAlreadyExistsException e) {
                try {
                    Thread.sleep((long) (Math.random() * 100) + 50);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw new IOException("获取锁被中断", ie);
                }
            }
        }
    }

    private interface LockedAction<T> {
        T execute() throws IOException;
    }
}
```

### 逐段详解

#### 1. 三种消息类型

|      类型       |   含义   |            示例            |
| :-------------: | :------: | :------------------------: |
|     `text`      | 普通消息 | "审查完了，发现 3 个问题"  |
|   `shutdown`    | 停止信号 |    Lead 让队员停止工作     |
| `plan_approval` | 计划审批 | 队员提交计划，等 Lead 批准 |

#### 2. 消息存储

```
mailbox/
├── alice/
│   ├── MSG-1234567890-001.json
│   └── MSG-1234567891-002.json
└── bob/
    └── MSG-1234567892-001.json
```

**每个成员一个目录，每条消息一个 JSON 文件。**

- 文件名带时间戳，天然有序
- 追加写，不需要改已有文件
- 标记已读是重写文件（read 字段改 true）

#### 3. 未读消息提醒

**队员的 Agent Loop 每轮开始前检查邮箱：**

```
// 在 AgentLoop 每轮开始时
List<Message> unread = mailbox.readUnread(memberId);
if (!unread.isEmpty()) {
    StringBuilder reminder = new StringBuilder();
    reminder.append("【未读消息】\n");
    for (Message msg : unread) {
        reminder.append("来自 ").append(msg.from())
            .append(" (").append(msg.type()).append("): ")
            .append(msg.subject()).append("\n");
        reminder.append(msg.content()).append("\n\n");
    }
    // 作为 system 消息注入
    history.add(new ChatMessage("system", reminder.toString()));
}
```

**队员下一轮就会看到：**

```
【未读消息】
来自 Lead (text): 任务分配
Alice，你负责审查 UserService 模块，重点看安全问题。
```

## 第五步：Coordinator Mode — 协调者模式

### 两把锁

```
// team/CoordinatorMode.java
package com.rook.team;

public class CoordinatorMode {

    /**
     * Coordinator 模式是否启用
     * 两把锁：feature flag + 环境变量，同时开启才生效
     */
    public static boolean isEnabled() {
        // 第一把锁：feature flag（配置文件里的开关）
        boolean featureEnabled = isFeatureEnabled();
        
        // 第二把锁：环境变量（运行时显式开启）
        boolean envEnabled = "true".equals(
            System.getenv("ROOK_COORDINATOR_MODE"));
        
        return featureEnabled && envEnabled;
    }

    private static boolean isFeatureEnabled() {
        // 从配置文件读取，默认 false
        // 实际实现从 AppConfig 里读
        return false;
    }

    /**
     * Lead 在 Coordinator 模式下的工具白名单
     */
    public static final List<String> LEAD_TOOL_WHITELIST = List.of(
        "agent",         // 派子 Agent（队员）
        "team_manage",   // 团队管理（增删成员）
        "task",          // 任务管理（创建/指派/查看）
        "send_message",  // 发消息
        "read_file",     // 只读
        "glob",
        "grep",
        "exec_command"   // 只读命令（git diff 等）
    );

    /**
     * Coordinator 模式下全局禁用的工具
     * Lead 不能直接改文件
     */
    public static final List<String> GLOBAL_DISALLOWED_FOR_LEAD = List.of(
        "write_file",
        "edit_file"
    );

    /**
     * 检查 Lead 能否使用某个工具
     */
    public static boolean canLeadUseTool(String toolName) {
        if (!isEnabled()) return true;  // 没开启 Coordinator 模式，不限制
        
        if (GLOBAL_DISALLOWED_FOR_LEAD.contains(toolName)) {
            return false;
        }
        return LEAD_TOOL_WHITELIST.contains(toolName);
    }
}
```

### 逐段详解

#### 1. 为什么要两把锁？

```
public static boolean isEnabled() {
    boolean featureEnabled = isFeatureEnabled();  // 配置文件开关
    boolean envEnabled = "true".equals(System.getenv("ROOK_COORDINATOR_MODE"));
    return featureEnabled && envEnabled;
}
```

**两把锁同时开启才生效：**

- 第一把：feature flag（配置文件里的 `coordinator_mode: true`）
- 第二把：环境变量 `ROOK_COORDINATOR_MODE=true`

**为什么要两把锁？**

- 防止误开启：只改配置或只设环境变量都不会生效
- 安全：Coordinator 模式限制了 Lead 的能力，开启要谨慎
- 灰度：可以在配置里打开，然后选择性地给某些会话设环境变量

#### 2. Lead 能做什么

|           能做           |          不能做           |
| :----------------------: | :-----------------------: |
|    派子 Agent（队员）    | 直接写文件（write_file）  |
|   管理团队（增删成员）   | 直接编辑文件（edit_file） |
| 管理任务（创建 / 指派）  |                           |
|          发消息          |                           |
|          读文件          |                           |
|    搜索（glob/grep）     |                           |
| 执行只读命令（git diff） |                           |

**Lead 只做决策和管理，不亲自动手写代码。**

- 要改代码？派队员去改
- 要审查？派 review 队员
- Lead 负责拆解任务、分配、汇总

#### 3. 防止 Lead 既当裁判又当运动员

**场景：** Lead 要审查代码

- 没有 Coordinator 模式：Lead 自己读代码、自己改、自己审查 → 不客观
- 有 Coordinator 模式：Lead 派 review 队员审查，自己只看结果 → 客观

**Coordinator 模式强制分工，保证质量。**

## 常见坑（详细版）

### 1. 锁文件并发冲突

**现象：** 多个队员同时写 TaskBoard，数据丢失。

**原因：** 没有加锁，后写的覆盖先写的。

**解决：**

- 用 `Files.createFile()` 原子创建锁文件（O_CREATE|O_EXCL）
- 抢不到锁的随机抖动后重试
- 所有读写操作都包在 withLock 里
- 锁文件在 finally 里删除，防止死锁

### 2. 锁文件死锁

**现象：** 锁文件一直存在，所有操作都卡住。

**原因：** 持有锁的进程崩了，没删锁文件。

**解决：**

- 锁文件带超时：超过 30 秒的锁文件认为是死锁，强制删除
- 或者用 `FileLock`（JVM 崩溃时 OS 自动释放）
- 简单实现可以加个锁超时检查

### 3. 队员续写（已停止的队员收到消息）

**现象：** 队员已经 stop 了，但收到消息后需要继续工作。

**原因：** 队员的 Agent Loop 已经退出，进程可能也结束了。

**解决：**

- 收到消息时检查队员状态
- 如果是 stopped，从 session 恢复历史，重新启动 Agent Loop
- 消息内容作为新的 user 消息注入
- 队员继续执行

### 4. Lead 不能写文件

**现象：** Coordinator 模式下 Lead 调用 write_file 被拒绝。

**原因：** 这是设计如此，Lead 只做决策不动手。

**解决：**

- Lead 应该派队员去写文件
- 工具返回明确的错误提示："Coordinator 模式下不能使用 write_file，请派队员"
- AI 看到错误会调整策略，派队员去做

### 5. 任务依赖死锁

**现象：** A 等 B，B 等 A，谁都做不了。

**原因：** 任务依赖形成循环。

**解决：**

- 创建任务时检测循环依赖（拓扑排序）
- 有循环依赖时拒绝创建，提示用户
- 或者 available () 里检测，循环依赖的任务都不算可认领

### 6. 消息丢失

**现象：** 发了消息但对方没收到。

**原因：** 接收者 ID 写错了，或者消息文件写入失败。

**解决：**

- 发送前检查接收者是否存在
- 写入失败抛异常，不静默
- 消息 ID 带时间戳，方便排查
- 可以加个已读回执

### 7. 团队数据损坏

**现象：** config.json 或 tasks.json 格式错误，加载失败。

**原因：** 写入时进程崩了，文件只写了一半。

**解决：**

- 原子写入：先写 .tmp，再 rename（和 WriteFileTool 一样）
- 加载失败时备份损坏文件，用空数据启动
- 定期备份

### 8. 队员数量太多

**现象：** 派了 10 个队员，系统卡死。

**原因：** 每个队员都是一个独立的 Agent Loop，占资源。

**解决：**

- 限制最大队员数量（比如 5 个）
- 队员用便宜的模型（haiku）
- 任务队列：超过限制的任务排队，有队员空闲了再派
- 或者用线程池控制并发

### 9. 任务状态不一致

**现象：** 任务显示 in-progress，但队员已经停了。

**原因：** 队员崩了，没更新任务状态。

**解决：**

- 定期检查队员状态，超时的任务标记为 blocked
- 或者任务带心跳，超过一定时间没更新就认为失败
- Lead 可以手动重置任务状态

### 10. Coordinator 模式误开启

**现象：** Lead 突然不能写文件了。

**原因：** 不小心设了环境变量或改了配置。

**解决：**

- 两把锁设计，必须同时开启才生效
- 启动时打印当前模式："Coordinator 模式：开启 / 关闭"
- 用户知道当前是什么模式

## 单 Agent vs 子 Agent vs 团队

|    维度     | 单 Agent |      子 Agent      |    团队（Team）     |
| :---------: | :------: | :----------------: | :-----------------: |
|    并行     |    否    |  可并行（但临时）  |   可并行（长期）    |
|   持久化    |  会话级  |       一次性       |    长期（存盘）     |
|  任务管理   |    无    |         无         | TaskBoard（带依赖） |
| 成员间通信  |    无    | 通过父 Agent 中转  |  Mailbox（点对点）  |
|  角色分工   |    无    | 有（defined 模式） |   有（长期角色）    |
| Coordinator |    无    |         无         |  有（Lead 只决策）  |
|  适用场景   | 简单任务 |    单次复杂任务    |  长期项目、大需求   |

**演进路径：**

- 简单任务 → 单 Agent
- 复杂任务 → 派几个子 Agent
- 长期项目 / 大需求 → 建团队，TaskBoard + Mailbox + Coordinator
