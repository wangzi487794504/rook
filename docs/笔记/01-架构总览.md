# 01 — 架构总览

## 这一章做什么

看懂 Rook 的 14 层模块架构——用户敲一行字到 AI 回复，中间经过哪些组件。

## 为什么需要

别一上来就写代码。先知道每个包是干什么的、谁调谁、数据怎么流。后面每章只聚焦一个包。

## 核心概念

- **分层架构**：cli → core → llm/tools/config/session/prompt/permission/mcp/skills/hook/team —— 每层只做一件事
- **单向依赖**：上层依赖下层，不反向。cli 知道所有，tools 不知道 llm
- **事件驱动**：AgentLoop 推 AgentEvent 到 BlockingQueue，UI 消费——互不阻塞

## 核心数据流（一次用户请求）

```
用户输入 "帮我读 pom.xml"
  │
  ▼
Repl.processMessage()                  — cli: 判断是命令还是对话
  │
  ▼
AgentLoop.run(history, provider, tools) — core: 进入 ReAct 循环
  │
  ├─ Round 1:
  │    PromptBuilder.build()            — prompt: 拼 System Prompt
  │    AnthropicProvider.stream()       — llm: POST /messages + 解析 SSE
  │    StreamCollector                  — llm: 实时 token + 累积 tool_use
  │    → toolCalls 非空
  │    ToolExecutor.execute()           — tools: 并发执行只读 + 串行执行写入
  │      └─ PermissionEngine.check()    — permission: 黑名单→沙箱→规则→模式
  │    → 结果回灌 history
  │
  ├─ Round 2:
  │    AnthropicProvider.stream()       — llm: 再次调 LLM（带工具结果）
  │    → toolCalls 空
  │    → 返回最终文本
  │
  ▼
Repl 消费 AgentEvent 事件 → 终端打印 → 回到 > 提示符
```

## 启动顺序

```
Main → App.run()
  1. ConfigLoader.load()          → 解析 config.yaml
  2. ProviderFactory.create()     → AnthropicProvider / OpenAiProvider
  3. ToolRegistry 注册 6 内置
  4. McpManager.discover()        → 发现 MCP 外部工具
  5. SkillLoader 加载 SKILL.md
  6. PermissionEngine 创建
  7. PromptBuilder 注册 10 模块
  8. Session.load()               → 恢复对话
  9. Repl.start()                 → 进入交互循环
```

## 常见坑

1. **循环依赖** → Rook 严格单向依赖。如果编译时 A 找不到 B，检查 import 是不是反了
2. **包太多记不住** → 不用记。每个包名就是它的职责。`llm` = LLM 调用，`tools` = 工具，`permission` = 权限
3. **"这个功能应该放哪个包"** → 问自己：这个类是给 LLM 用的（llm）、给工具用的（tools）、还是给用户界面用的（cli）？
