# 05 — 配置加载 + 会话持久化

## 这一章做什么

用 **SnakeYAML** 加载 `config.yaml` 配置文件，用 **Jackson** 把对话历史存到 JSON 文件。

**完成后你能做到：**

- API Key、模型配置都写在配置文件里，不用硬编码
- 修改配置不用重新编译
- 关掉程序再打开，之前的对话历史还在，可以继续聊

## 为什么需要

### 没有配置文件的问题

- API Key 硬编码在代码里 → 不安全，容易泄露
- 想换个模型要改代码 → 麻烦，还要重新编译
- 不同环境（开发 / 生产）用不同配置 → 没法切换

### 没有会话持久化的问题

- 每次启动都是空白对话 → 不方便
- 重要的对话内容丢了就没了 → 不放心
- 想回顾之前聊了什么 → 做不到

**这一章解决这两个问题。**

## 核心概念

### SnakeYAML

Java 里最常用的 YAML 解析库。

**什么是 YAML？**

一种配置文件格式，比 JSON 更适合人写：

- 不用写大括号、方括号
- 用缩进表示层级
- 支持注释

**YAML 示例：**

```yaml
# 这是注释
default_provider: deepseek

providers:
  - name: deepseek
    protocol: anthropic
    model: deepseek-v4-pro
    base_url: https://api.deepseek.com/anthropic
    api_key: sk-xxx
```

### ConfigLoader

配置加载器，负责：

- 读取 YAML 文件
- 解析成 Java 对象
- 校验配置是否合法（有没有缺字段、protocol 对不对）

**为什么要校验？**

配置文件是用户写的，可能写错：

- 漏了必填字段
- protocol 拼错了
- default_provider 指向了一个不存在的模型

启动时就检查出来，比运行到一半才报错好。

### Session

会话对象，管理对话历史：

- 内存里存着消息列表
- 可以保存到文件
- 可以从文件加载回来

**为什么需要 Session 类？**

- 封装历史消息的操作（添加、清空、保存、加载）
- 上层不用关心消息存在哪、怎么存
- 以后换存储方式（比如存数据库），上层不用改

## 第一步：ConfigLoader

```java
// config/ConfigLoader.java
package com.rook.config;

import org.yaml.snakeyaml.Yaml;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.*;

public class ConfigLoader {

    // 合法的协议列表
    private static final List<String> VALID_PROTOCOLS = List.of("anthropic", "openai");

    @SuppressWarnings("unchecked")
    public static AppConfig load(Path path) throws IOException {
        // 1. 检查文件是否存在
        if (!Files.exists(path)) {
            throw new IOException("配置文件不存在: " + path.toAbsolutePath());
        }

        // 2. 解析 YAML
        Yaml yaml = new Yaml();
        Map<String, Object> root = yaml.load(Files.newInputStream(path));
        if (root == null) throw new IOException("配置文件为空");

        // 3. 解析 default_provider
        String defaultProvider = (String) root.get("default_provider");
        if (defaultProvider == null || defaultProvider.isBlank())
            throw new IllegalStateException("缺少 default_provider");

        // 4. 解析 providers 列表
        List<Map<String, Object>> providerMaps =
            (List<Map<String, Object>>) root.get("providers");
        if (providerMaps == null || providerMaps.isEmpty())
            throw new IllegalStateException("providers 不能为空");

        List<ProviderConfig> providers = providerMaps.stream()
            .map(ConfigLoader::parseProvider)
            .toList();

        // 5. 校验 default_provider 是否存在
        boolean exists = providers.stream()
            .anyMatch(p -> p.name().equals(defaultProvider));
        if (!exists) throw new IllegalStateException("default_provider 不在列表中");

        return new AppConfig(providers, defaultProvider);
    }

    // 解析单个 provider
    private static ProviderConfig parseProvider(Map<String, Object> map) {
        String name = require(map, "name");
        String protocol = require(map, "protocol").toLowerCase();
        String model = require(map, "model");
        String baseUrl = require(map, "base_url");
        String apiKey = require(map, "api_key");

        // 校验 protocol 是否合法
        if (!VALID_PROTOCOLS.contains(protocol))
            throw new IllegalStateException(name + ": protocol 不合法: " + protocol);

        return new ProviderConfig(name, protocol, model, baseUrl, apiKey);
    }

    // 工具方法：获取必填字段，缺失就报错
    private static String require(Map<String, Object> map, String key) {
        Object v = map.get(key);
        if (v == null || v.toString().isBlank())
            throw new IllegalStateException("缺少字段: " + key);
        return v.toString().trim();
    }
}
```

### 逐段详解

#### 1. 合法协议列表

```
private static final List<String> VALID_PROTOCOLS = List.of("anthropic", "openai");
```

白名单，只有这两个协议是合法的。用户写了别的就报错。

**为什么用白名单？**

- 防止用户拼写错误（比如写成 `antropic` 少了个 h）
- 启动时就发现问题，不用等到运行时
- 以后加新协议，往这个列表里加就行

#### 2. load () 方法 — 主入口

```
public static AppConfig load(Path path) throws IOException {
```

- 静态方法，直接 `ConfigLoader.load(path)` 调用
- 输入：配置文件路径
- 输出：解析好的 AppConfig 对象

##### 第一步：检查文件是否存在

```java
if (!Files.exists(path)) {
    throw new IOException("配置文件不存在: " + path.toAbsolutePath());
}
```

文件不存在就直接报错，并且把绝对路径打出来，方便用户找。

**为什么要提前检查？**

- 不检查的话，后面 `Files.newInputStream` 也会报错
- 但提前检查可以给出更友好的错误信息
- 用户一看就知道 "哦，配置文件放错地方了"

##### 第二步：解析 YAML

```java
Yaml yaml = new Yaml();
Map<String, Object> root = yaml.load(Files.newInputStream(path));
if (root == null) throw new IOException("配置文件为空");
```

**SnakeYAML 的用法：**

- 创建一个 `Yaml` 对象
- 调用 `load()` 方法，传一个 InputStream
- 返回的是 `Map<String, Object>`，就是 YAML 的根对象

**为什么是 Map 不是专门的配置类？**

- SnakeYAML 可以直接映射到 Java 对象，但需要写注解
- 用 Map 更灵活，不用改配置类
- 对于简单的配置，Map 够用了

**`root == null` 是什么情况？**

配置文件是空的，或者全是注释，没有实际内容。

##### 第三步：解析 default_provider

```java
String defaultProvider = (String) root.get("default_provider");
if (defaultProvider == null || defaultProvider.isBlank())
    throw new IllegalStateException("缺少 default_provider");
```

从 Map 里取 `default_provider` 字段，转成 String。

**为什么要判空？**

- 用户可能忘了写这个字段
- 不检查的话，后面用的时候会 NullPointerException
- 提前检查，给出清晰的错误信息

##### 第四步：解析 providers 列表

```java
List<Map<String, Object>> providerMaps =
    (List<Map<String, Object>>) root.get("providers");
if (providerMaps == null || providerMaps.isEmpty())
    throw new IllegalStateException("providers 不能为空");

List<ProviderConfig> providers = providerMaps.stream()
    .map(ConfigLoader::parseProvider)
    .toList();
```

**两步：**

1. 从 Map 里取 `providers` 字段，它是一个列表
2. 遍历列表，每个元素调用 `parseProvider()` 转成 `ProviderConfig` 对象

**为什么用 stream ().map ()？**

- 链式调用，代码简洁
- 比 for 循环更声明式

##### 第五步：校验 default_provider

```java
boolean exists = providers.stream()
    .anyMatch(p -> p.name().equals(defaultProvider));
if (!exists) throw new IllegalStateException("default_provider 不在列表中");
```

检查 default_provider 指向的名字，在 providers 列表里能不能找到。

**举个例子：**

```yaml
default_provider: gpt  ← 写的是 gpt

providers:
  - name: deepseek    ← 但列表里只有 deepseek
    ...
```

这种情况就会报错，告诉用户 "你默认用的那个模型不存在"。

**`anyMatch()` 是什么？**

Stream 的方法，只要有一个元素满足条件就返回 true。

#### 3. parseProvider () — 解析单个 provider

```java
private static ProviderConfig parseProvider(Map<String, Object> map) {
    String name = require(map, "name");
    String protocol = require(map, "protocol").toLowerCase();
    String model = require(map, "model");
    String baseUrl = require(map, "base_url");
    String apiKey = require(map, "api_key");

    if (!VALID_PROTOCOLS.contains(protocol))
        throw new IllegalStateException(name + ": protocol 不合法: " + protocol);

    return new ProviderConfig(name, protocol, model, baseUrl, apiKey);
}
```

**做了三件事：**

1. 取出每个字段（用 `require()` 方法，缺失就报错）
2. protocol 转小写（容错，用户写 `Anthropic` 也能识别）
3. 校验 protocol 是否合法

**为什么 protocol 转小写？**

用户可能写 `Anthropic`、`ANTHROPIC`、`anthropic`，都应该识别。统一转成小写再比较。

#### 4. require () — 工具方法

```java
private static String require(Map<String, Object> map, String key) {
    Object v = map.get(key);
    if (v == null || v.toString().isBlank())
        throw new IllegalStateException("缺少字段: " + key);
    return v.toString().trim();
}
```

**获取必填字段的工具方法。**

**逻辑：**

1. 从 Map 里取值
2. 如果是 null 或者空白字符串 → 报错
3. 否则转成 String，去掉首尾空白，返回

**为什么要抽这个方法？**

- 五个字段都要判空，重复代码太多
- 抽成方法，一行搞定一个字段
- 以后改校验逻辑，只改这一个地方

## 第二步：Session

```java
// session/Session.java
package com.rook.session;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.rook.llm.ChatMessage;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.*;

public class Session {

    private static final ObjectMapper MAPPER = new ObjectMapper();
    
    // 消息列表（内存）
    private final List<ChatMessage> messages = new ArrayList<>();

    // 获取消息列表（只读）
    public List<ChatMessage> getMessages() {
        return Collections.unmodifiableList(messages);
    }

    // 添加一条消息
    public void addMessage(ChatMessage msg) {
        messages.add(msg);
    }

    // 清空对话
    public void clear() {
        messages.clear();
    }

    // 保存到文件
    public void save(Path path) throws IOException {
        Files.createDirectories(path.getParent());  // 确保目录存在
        MAPPER.writerWithDefaultPrettyPrinter()     // 美化输出
              .writeValue(path.toFile(), messages);
    }

    // 从文件加载
    public static Session load(Path path) throws IOException {
        if (!Files.exists(path)) return new Session();  // 文件不存在就返回空会话
        
        List<ChatMessage> msgs = MAPPER.readValue(
            path.toFile(),
            MAPPER.getTypeFactory().constructCollectionType(List.class, ChatMessage.class)
        );
        
        Session s = new Session();
        msgs.forEach(s::addMessage);
        return s;
    }
}
```

### 逐段详解

#### 1. 字段

```
private static final ObjectMapper MAPPER = new ObjectMapper();
private final List<ChatMessage> messages = new ArrayList<>();
```

- `MAPPER` — Jackson 的 ObjectMapper，用来序列化和反序列化 JSON
- `messages` — 消息列表，存在内存里

**为什么 MAPPER 是 static final？**

- ObjectMapper 是线程安全的，可以全局共享
- 不用每次都创建新的，性能更好

#### 2. getMessages () — 获取消息列表

```
public List<ChatMessage> getMessages() {
    return Collections.unmodifiableList(messages);
}
```

**返回的是不可修改的列表。**

**为什么？**

防止外部代码直接修改内部的 messages 列表，破坏封装。

**如果外部想加消息怎么办？**

用 `addMessage()` 方法，走正规渠道。

**`Collections.unmodifiableList()` 是什么？**

把列表包装成只读的，外部调用 `add()`、`remove()` 会抛 `UnsupportedOperationException`。

#### 3. addMessage () — 添加消息

```
public void addMessage(ChatMessage msg) {
    messages.add(msg);
}
```

简单，往列表里加一条。

**为什么不直接暴露 messages？**

- 封装内部状态
- 以后想加逻辑（比如限制最大消息数、自动保存），直接在这个方法里加，外部不用改

#### 4. clear () — 清空对话

```java
public void clear() {
    messages.clear();
}
```

清空所有消息，开始新对话。

#### 5. save () — 保存到文件

```java
public void save(Path path) throws IOException {
    Files.createDirectories(path.getParent());
    MAPPER.writerWithDefaultPrettyPrinter()
          .writeValue(path.toFile(), messages);
}
```

**两步：**

##### 第一步：确保目录存在

```
Files.createDirectories(path.getParent());
```

如果保存路径的父目录不存在，就创建它。

**比如：**

路径是 `~/.rook/sessions/default.json`

- 父目录是 `~/.rook/sessions/`
- 如果这个目录不存在，先创建
- 不然写文件会报错

**`createDirectories()` 和 `createDirectory()` 的区别：**

- `createDirectory()` — 只创建一层，父目录不存在就报错
- `createDirectories()` — 递归创建所有不存在的父目录

##### 第二步：写 JSON 文件

```
MAPPER.writerWithDefaultPrettyPrinter()
      .writeValue(path.toFile(), messages);
```

**`writerWithDefaultPrettyPrinter()` 是什么？**

美化输出，JSON 带缩进和换行，人能看懂。

**没有它的话：**

```
[{"role":"user","content":"你好"},{"role":"assistant","content":"你好！"}]
```

**有它的话：**

```
[ {
  "role" : "user",
  "content" : "你好"
}, {
  "role" : "assistant",
  "content" : "你好！"
} ]
```

格式化的 JSON 方便用户查看和编辑。

#### 6. load () — 从文件加载

```java
public static Session load(Path path) throws IOException {
    // 文件不存在就返回空会话
    if (!Files.exists(path)) return new Session();
    
    // 解析 JSON
    List<ChatMessage> msgs = MAPPER.readValue(
        path.toFile(),
        MAPPER.getTypeFactory().constructCollectionType(List.class, ChatMessage.class)
    );
    
    // 组装成 Session 对象
    Session s = new Session();
    msgs.forEach(s::addMessage);
    return s;
}
```

**三步：**

##### 第一步：文件不存在就返回空会话

```
if (!Files.exists(path)) return new Session();
```

第一次运行，还没有会话文件，这是正常的，返回一个空的 Session 就行，不要报错。

##### 第二步：解析 JSON

```
List<ChatMessage> msgs = MAPPER.readValue(
    path.toFile(),
    MAPPER.getTypeFactory().constructCollectionType(List.class, ChatMessage.class)
);
```

**为什么这么复杂？不能直接 `List<ChatMessage>.class` 吗？**

因为 Java 的泛型擦除，运行时 `List<ChatMessage>` 和 `List<String>` 是同一个 Class 对象，Jackson 不知道里面是什么类型。

**所以要用 TypeFactory 来构造完整的类型信息：**

```
constructCollectionType(List.class, ChatMessage.class)
```

告诉 Jackson：这是一个 List，里面的元素是 ChatMessage 类型。

##### 第三步：组装 Session

```
Session s = new Session();
msgs.forEach(s::addMessage);
return s;
```

创建一个新的 Session，把解析出来的消息都加进去。

**为什么不直接把 list 传进去？**

- 保持封装，通过 addMessage () 方法添加
- 以后 addMessage () 里加了逻辑（比如去重、截断），这里自动生效

## 完整流程

```
程序启动
  │
  ▼
App.run()
  │
  ├─ 1. ConfigLoader.load(configPath)
  │     │
  │     ├─ 检查文件是否存在
  │     ├─ 解析 YAML → Map
  │     ├─ 提取 default_provider
  │     ├─ 解析 providers 列表
  │     ├─ 校验配置合法性
  │     └─ 返回 AppConfig
  │
  ├─ 2. ProviderFactory.create(appConfig)
  │     └─ 创建所有 LLM Provider
  │
  ├─ 3. Session.load(sessionPath)
  │     │
  │     ├─ 文件存在吗？
  │     │   ├─ 存在 → 解析 JSON → 恢复消息
  │     │   └─ 不存在 → 空会话
  │     └─ 返回 Session 对象
  │
  └─ 4. Repl.start()
        │
        └─ 交互循环
             │
             用户输入 → AI 回复 → 消息加入 Session
             │
             ...
             │
             用户输入 /exit
             │
             ▼
          session.save() → 保存到文件
             │
             ▼
          程序退出
```

## 常见坑（详细版）

### 1. YAML 缩进用空格不能用 Tab

**现象：** 解析报错，说格式不对。

**原因：** YAML 严格规定缩进必须用空格，不能用 Tab。

**解决：**

- 编辑器里设置 "把 Tab 转换成空格"
- 一般用 2 个空格缩进

**错误示例：**

```
providers:
	- name: deepseek   ← 这里用了 Tab，错的
```

**正确示例：**

```
providers:
  - name: deepseek   ← 两个空格，对的
```

### 2. 会话文件路径用 `~/.rook/`

**不要放在项目目录里。**

**为什么？**

- 项目删了，会话还在
- 多个项目可以共用同一份配置和会话
- 符合 Unix 习惯（用户数据存在 home 目录）

**路径示例：**

- 配置：`~/.rook/config.yaml`
- 会话：`~/.rook/sessions/default.json`

**`~` 是什么？**

用户 home 目录的缩写。

- Windows: `C:\Users\用户名\.rook\`
- macOS/Linux: `/home/用户名/.rook/`

**Java 里怎么解析 `~`？**

```
Path path = Path.of(System.getProperty("user.home"), ".rook", "config.yaml");
```

### 3. `save()` 后没 `flush()`

**现象：** 保存了但文件是空的，或者内容不全。

**原因：** 输出流有缓冲区，没 flush 就关闭了，数据还在缓冲区里。

**Jackson 的 `writeValue()` 会自动 flush 和 close 吗？**

会的。Jackson 内部会确保写完后 flush，并且关闭流。所以一般不用担心。

**但如果你用 `Files.writeString()` 这种低级 API，要注意：**

```
// 这样写是安全的，Files.writeString 会自动关闭
Files.writeString(path, content);

// 但如果自己开流，要记得 flush 和 close
try (Writer writer = Files.newBufferedWriter(path)) {
    writer.write(content);
    writer.flush();  // 手动 flush
}
```

### 4. 配置文件里的 api_key 泄露

**现象：** 配置文件提交到 GitHub，api_key 泄露了。

**原因：** 把 `config.yaml` 加到了 git 里。

**解决：**

1. `.gitignore` 里加上 `config.yaml`
2. 或者用环境变量存密钥，配置文件只放变量名
3. 或者提供一个 `config.example.yaml` 模板，用户自己复制改名

### 5. 会话文件太大

**现象：** 聊了几千条消息，JSON 文件很大，加载变慢。

**解决：**

- 限制最大消息数，比如最多保留 100 条
- 或者做会话分片，按日期分文件
- 或者只保留最近 N 轮对话

**简单实现：**

```java
public void addMessage(ChatMessage msg) {
    messages.add(msg);
    // 超过 100 条就删最老的
    if (messages.size() > 100) {
        messages.remove(0);
    }
}
```

### 6. SnakeYAML 版本问题

**现象：** 启动报错，说找不到某个类。

**原因：** SnakeYAML 有大版本升级（1.x → 2.x），API 有变化。

**解决：**

- 用稳定版本，比如 SnakeYAML 2.0+
- pom.xml 里明确指定版本
