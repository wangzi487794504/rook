# 22 — 联网搜索：GLM API + HTML 备胎

## 这一章做什么

实现 `web_search` 工具。优先走**智谱 GLM Web Search API**（结构化 JSON、中文质量好），API 不可用时自动降级到 **Bing HTML 抓取**（免费、零配置）。

**完成后你能做到：**

- 查最新文档？`web_search("Java 21 虚拟线程")` → 结构化结果
- API 挂了？自动切 Bing HTML，用户无感
- 没配 API key？直接走 HTML，零配置能用
- AI 的知识不再有截止日期

## 为什么需要

### LLM 的知识截止问题

所有大模型都有知识截止日期：

- Claude 3.5：2024 年 4 月
- GPT-4o：2023 年 10 月
- DeepSeek V3：2024 年 5 月

**超过这个日期的信息，AI 不知道，只能猜。**

**场景：**

- "Java 22 有什么新特性？" → AI 可能不知道
- "这个库最新版的 API 怎么用？" → AI 可能用旧版 API
- "今天有什么技术新闻？" → AI 完全不知道
- "这个错误怎么解决？" → 可能是新出现的问题

### 搜索能力的价值

```
没有搜索：AI 只能用训练数据里的知识，过时了就错
有搜索：  AI 可以实时查互联网，信息永远最新
```

**搜索是 AI Agent 从 "闭卷考试" 变成 "开卷考试" 的关键能力。**

## 核心概念

### 双通道设计

|     通道      |            优点             |        缺点        |     适用场景     |
| :-----------: | :-------------------------: | :----------------: | :--------------: |
|  **GLM API**  | 结构化 JSON、中文好、有摘要 | 付费、需要 API key | 有 key、追求质量 |
| **Bing HTML** |   免费、零配置、随时可用    | 解析脆弱、质量稍差 | 没 key、API 挂了 |

### 自动降级

- 优先走 GLM API
- API 超时、余额不足、返回错误 → catch 块自动切 HTML
- 用户无感，搜索永远能用

### 环境变量驱动

- 设了 `GLM_SEARCH_API_KEY` → 走 API（主通道）
- 没设 → 直接走 HTML（备胎）
- 不用改代码，环境变量控制

## 第一步：WebSearchTool — 工具定义

```
// tools/impl/WebSearchTool.java
package com.rook.tools.impl;

import com.rook.tools.Tool;
import com.rook.tools.ToolResult;
import java.util.List;
import java.util.Map;

public class WebSearchTool implements Tool {

    private static final int DEFAULT_COUNT = 5;
    private static final int MAX_COUNT = 10;

    private final GlmSearchClient glmClient;
    private final BingHtmlSearch bingClient;

    public WebSearchTool() {
        this.glmClient = new GlmSearchClient();
        this.bingClient = new BingHtmlSearch();
    }

    @Override
    public String name() {
        return "web_search";
    }

    @Override
    public String description() {
        return "搜索互联网获取最新信息。当需要查询最新的文档、新闻、API 用法、"
            + "或任何可能超出知识截止日期的信息时使用。";
    }

    @Override
    public Map<String, Object> inputSchema() {
        return Map.of(
            "type", "object",
            "properties", Map.of(
                "query", Map.of(
                    "type", "string",
                    "description", "搜索关键词"
                ),
                "count", Map.of(
                    "type", "integer",
                    "description", "返回结果数量，默认 5，最多 10",
                    "default", 5
                )
            ),
            "required", List.of("query")
        );
    }

    @Override
    public ToolResult execute(Map<String, Object> params) {
        String query = (String) params.get("query");
        if (query == null || query.isBlank()) {
            return ToolResult.error("query 不能为空");
        }

        int count = DEFAULT_COUNT;
        if (params.get("count") instanceof Number n) {
            count = Math.min(n.intValue(), MAX_COUNT);
        }

        // ★ 环境变量驱动：有 key 走 API，没 key 走 HTML
        String apiKey = System.getenv("GLM_SEARCH_API_KEY");
        if (apiKey != null && !apiKey.isBlank()) {
            try {
                return glmClient.search(query, count, apiKey);  // 主通道
            } catch (Exception e) {
                System.err.println("[Search] GLM API 失败，降级到 HTML: " 
                    + e.getMessage());
                // 降级到 HTML 备胎
                return bingClient.search(query, count);
            }
        }

        // 没配 key，直接走 HTML
        return bingClient.search(query, count);
    }
}
```

### 逐段详解

#### 1. 工具描述很重要

```
@Override
public String description() {
    return "搜索互联网获取最新信息。当需要查询最新的文档、新闻、API 用法、"
        + "或任何可能超出知识截止日期的信息时使用。";
}
```

**description 决定了 AI 什么时候调用这个工具。**

写得清楚，AI 才知道：

- 查最新信息时用
- 查可能过时的知识时用
- 不是所有问题都要搜（比如 "1+1 等于几" 不用搜）

#### 2. 双通道入口

```
String apiKey = System.getenv("GLM_SEARCH_API_KEY");
if (apiKey != null && !apiKey.isBlank()) {
    try {
        return glmClient.search(query, count, apiKey);  // 主通道
    } catch (Exception e) {
        System.err.println("[Search] GLM API 失败，降级到 HTML: " + e.getMessage());
        return bingClient.search(query, count);  // 降级
    }
}
return bingClient.search(query, count);  // 没 key，直接 HTML
```

**逻辑：**

1. 有 API key → 尝试 GLM API
2. GLM API 成功 → 返回结果
3. GLM API 失败（任何异常）→ 降级到 Bing HTML
4. 没 API key → 直接 Bing HTML

**★ 自动降级的关键：catch 所有异常，不抛出去。**

不管是网络超时、余额不足、API 改版，都 catch 住，切备胎。

#### 3. count 限制

```
int count = DEFAULT_COUNT;
if (params.get("count") instanceof Number n) {
    count = Math.min(n.intValue(), MAX_COUNT);
}
```

- 默认 5 条
- 最多 10 条（太多了占 token）
- AI 传了更大的数，截断到 10

## 第二步：GLM API — 主通道

### API 文档

```
端点：POST https://open.bigmodel.cn/api/paas/v4/web_search
认证：Authorization: Bearer {api_key}
Content-Type: application/json

请求体：
{
  "search_query": "关键词",
  "search_engine": "search_pro",
  "search_intent": false,
  "count": 5
}

响应：
{
  "search_result": [
    {
      "title": "标题",
      "content": "内容摘要",
      "link": "https://..."
    },
    ...
  ]
}
```

### 实现代码

```
// tools/impl/GlmSearchClient.java
package com.rook.tools.impl;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.rook.tools.ToolResult;
import java.net.URI;
import java.net.http.*;
import java.nio.charset.StandardCharsets;
import java.time.Duration;
import java.util.*;

public class GlmSearchClient {

    private static final String ENDPOINT = 
        "https://open.bigmodel.cn/api/paas/v4/web_search";
    private static final ObjectMapper MAPPER = new ObjectMapper();
    private static final HttpClient HTTP = HttpClient.newBuilder()
        .connectTimeout(Duration.ofSeconds(5))
        .build();

    public ToolResult search(String query, int count, String apiKey) throws Exception {
        // 构建请求体
        Map<String, Object> body = Map.of(
            "search_query", query,
            "search_engine", "search_pro",
            "search_intent", false,
            "count", count
        );
        String jsonBody = MAPPER.writeValueAsString(body);

        // 构建请求
        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create(ENDPOINT))
            .header("Authorization", "Bearer " + apiKey)
            .header("Content-Type", "application/json")
            .timeout(Duration.ofSeconds(15))
            .POST(HttpRequest.BodyPublishers.ofString(jsonBody, StandardCharsets.UTF_8))
            .build();

        // 发送请求
        HttpResponse<String> response = HTTP.send(
            request, 
            HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8)
        );

        // 检查状态码
        if (response.statusCode() != 200) {
            throw new RuntimeException(
                "GLM API 返回 " + response.statusCode() + ": " + response.body());
        }

        // 解析响应
        JsonNode root = MAPPER.readTree(response.body());
        JsonNode results = root.path("search_result");

        if (!results.isArray() || results.isEmpty()) {
            return ToolResult.ok("未找到相关结果");
        }

        // 格式化结果
        return ToolResult.ok(formatResults(results));
    }

    /**
     * 格式化搜索结果为易读文本
     */
    private String formatResults(JsonNode results) {
        StringBuilder sb = new StringBuilder();
        sb.append("搜索结果（共 ").append(results.size()).append(" 条）：\n\n");

        int i = 1;
        for (JsonNode item : results) {
            String title = item.path("title").asText("无标题");
            String content = item.path("content").asText("");
            String link = item.path("link").asText("");

            sb.append(i).append(". ").append(title).append("\n");
            if (!link.isBlank()) {
                sb.append("   链接: ").append(link).append("\n");
            }
            if (!content.isBlank()) {
                // 内容截断，避免太长
                String truncated = content.length() > 300 
                    ? content.substring(0, 300) + "..." 
                    : content;
                sb.append("   摘要: ").append(truncated).append("\n");
            }
            sb.append("\n");
            i++;
        }

        return sb.toString();
    }
}
```

### 逐段详解

#### 1. 请求参数

```
Map<String, Object> body = Map.of(
    "search_query", query,
    "search_engine", "search_pro",
    "search_intent", false,
    "count", count
);
```

|      参数       |       含义       |                   说明                   |
| :-------------: | :--------------: | :--------------------------------------: |
| `search_query`  |    搜索关键词    |                   必填                   |
| `search_engine` |     搜索引擎     |     `search_pro` 是专业版，质量更好      |
| `search_intent` | 是否启用意图识别 | false = 直接搜，true = AI 先理解意图再搜 |
|     `count`     |     返回数量     |                 最多 10                  |

#### 2. 超时设置

```
private static final HttpClient HTTP = HttpClient.newBuilder()
    .connectTimeout(Duration.ofSeconds(5))
    .build();

.timeout(Duration.ofSeconds(15))
```

**两个超时：**

- 连接超时：5 秒（连不上服务器）
- 请求超时：15 秒（连上了但响应慢）

**为什么要设超时？**

- 不设超时的话，网络不好时会一直等
- 15 秒比较合理，搜索一般几秒就返回
- 超时了就抛异常，触发降级

#### 3. 状态码检查

```
if (response.statusCode() != 200) {
    throw new RuntimeException("GLM API 返回 " + response.statusCode() + ": " + response.body());
}
```

非 200 状态码抛异常，触发降级。

**常见错误码：**

- 401：API key 无效
- 402：余额不足
- 429：请求太频繁（限流）
- 500：服务器内部错误

#### 4. 结果格式化

```
private String formatResults(JsonNode results) {
    StringBuilder sb = new StringBuilder();
    sb.append("搜索结果（共 ").append(results.size()).append(" 条）：\n\n");
    for (JsonNode item : results) {
        sb.append(i).append(". ").append(title).append("\n");
        sb.append("   链接: ").append(link).append("\n");
        sb.append("   摘要: ").append(truncated).append("\n");
    }
    return sb.toString();
}
```

**把结构化 JSON 转成易读文本：**

- 编号
- 标题
- 链接
- 摘要（截断到 300 字符）

**为什么要截断？**

- 搜索结果的摘要可能很长
- 全部给 AI 占 token
- 截断到 300 字符，AI 需要详细内容可以自己打开链接

## 第三步：Bing HTML — 备胎

### 原理

直接抓取 Bing 搜索结果页面，解析 HTML 提取标题和链接。

```
GET https://cn.bing.com/search?q=关键词
    │
    ▼
HTML 页面
    │
    ▼
解析 <li class="b_algo"> 元素
    ├─ <h2><a> 标题和链接
    └─ <cite> 域名
```

### 实现代码

```
// tools/impl/BingHtmlSearch.java
package com.rook.tools.impl;

import com.rook.tools.ToolResult;
import java.io.IOException;
import java.net.URI;
import java.net.URLEncoder;
import java.net.http.*;
import java.nio.charset.StandardCharsets;
import java.time.Duration;
import java.util.*;
import java.util.regex.*;

public class BingHtmlSearch {

    private static final String BING_URL = "https://cn.bing.com/search?q=";
    private static final HttpClient HTTP = HttpClient.newBuilder()
        .connectTimeout(Duration.ofSeconds(5))
        .build();

    // 匹配搜索结果项：<li class="b_algo">...</li>
    private static final Pattern RESULT_PATTERN = Pattern.compile(
        "<li[^>]*class=\"b_algo\"[^>]*>(.*?)</li>",
        Pattern.DOTALL
    );

    // 匹配标题和链接：<h2><a href="链接">标题</a></h2>
    private static final Pattern TITLE_PATTERN = Pattern.compile(
        "<h2[^>]*>\\s*<a[^>]*href=\"([^\"]+)\"[^>]*>(.*?)</a>\\s*</h2>",
        Pattern.DOTALL
    );

    // 匹配摘要：<p> 或 <div class="b_caption">
    private static final Pattern SNIPPET_PATTERN = Pattern.compile(
        "<p[^>]*>(.*?)</p>",
        Pattern.DOTALL
    );

    public ToolResult search(String query, int count) {
        try {
            String url = BING_URL + URLEncoder.encode(query, StandardCharsets.UTF_8);

            HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create(url))
                .header("User-Agent", 
                    "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                    + "AppleWebKit/537.36 (KHTML, like Gecko) "
                    + "Chrome/120.0.0.0 Safari/537.36")
                .header("Accept-Language", "zh-CN,zh;q=0.9")
                .timeout(Duration.ofSeconds(10))
                .GET()
                .build();

            HttpResponse<String> response = HTTP.send(
                request,
                HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8)
            );

            if (response.statusCode() != 200) {
                return ToolResult.error("Bing 搜索失败: HTTP " + response.statusCode());
            }

            List<SearchResult> results = parseHtml(response.body(), count);
            if (results.isEmpty()) {
                return ToolResult.ok("未找到相关结果（HTML 解析可能失效）");
            }

            return ToolResult.ok(formatResults(results, query));

        } catch (Exception e) {
            return ToolResult.error("Bing 搜索失败: " + e.getMessage());
        }
    }

    /**
     * 解析 HTML 提取搜索结果
     */
    private List<SearchResult> parseHtml(String html, int count) {
        List<SearchResult> results = new ArrayList<>();

        Matcher resultMatcher = RESULT_PATTERN.matcher(html);
        while (resultMatcher.find() && results.size() < count) {
            String itemHtml = resultMatcher.group(1);

            // 提取标题和链接
            Matcher titleMatcher = TITLE_PATTERN.matcher(itemHtml);
            if (titleMatcher.find()) {
                String link = titleMatcher.group(1);
                String title = stripHtml(titleMatcher.group(2));

                // 提取摘要
                String snippet = "";
                Matcher snippetMatcher = SNIPPET_PATTERN.matcher(itemHtml);
                if (snippetMatcher.find()) {
                    snippet = stripHtml(snippetMatcher.group(1));
                }

                results.add(new SearchResult(title, link, snippet));
            }
        }

        return results;
    }

    /**
     * 去除 HTML 标签
     */
    private String stripHtml(String html) {
        return html.replaceAll("<[^>]+>", "")  // 去标签
                   .replaceAll("&nbsp;", " ")
                   .replaceAll("&amp;", "&")
                   .replaceAll("&lt;", "<")
                   .replaceAll("&gt;", ">")
                   .replaceAll("&quot;", "\"")
                   .trim();
    }

    private String formatResults(List<SearchResult> results, String query) {
        StringBuilder sb = new StringBuilder();
        sb.append("搜索结果（共 ").append(results.size()).append(" 条）：\n");
        sb.append("关键词: ").append(query).append("\n\n");

        int i = 1;
        for (SearchResult r : results) {
            sb.append(i).append(". ").append(r.title()).append("\n");
            sb.append("   链接: ").append(r.link()).append("\n");
            if (!r.snippet().isBlank()) {
                String truncated = r.snippet().length() > 200 
                    ? r.snippet().substring(0, 200) + "..." 
                    : r.snippet();
                sb.append("   摘要: ").append(truncated).append("\n");
            }
            sb.append("\n");
            i++;
        }

        return sb.toString();
    }

    private record SearchResult(String title, String link, String snippet) {}
}
```

### 逐段详解

#### 1. 为什么用 [cn.bing.com](https://link.wtturl.cn/?target=https%3A%2F%2Fcn.bing.com&scene=im&aid=497858&lang=zh)？

```
private static final String BING_URL = "https://cn.bing.com/search?q=";
```

**`cn.bing.com` vs `www.bing.com`：**

- `cn.bing.com`：国内版，国内直连，不需要翻墙
- `www.bing.com`：国际版，可能被墙，国内访问不稳定

**国内用户用 [cn.bing.com](https://link.wtturl.cn/?target=https%3A%2F%2Fcn.bing.com&scene=im&aid=497858&lang=zh)，稳定。**

#### 2. User-Agent 伪装

```
.header("User-Agent", 
    "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
    + "AppleWebKit/537.36 (KHTML, like Gecko) "
    + "Chrome/120.0.0.0 Safari/537.36")
```

**为什么要伪装浏览器？**

- 不设 User-Agent，Bing 可能返回简化版页面或拒绝访问
- 伪装成 Chrome 浏览器，拿到正常的搜索结果页面

#### 3. 正则解析 HTML

```
private static final Pattern RESULT_PATTERN = Pattern.compile(
    "<li[^>]*class=\"b_algo\"[^>]*>(.*?)</li>",
    Pattern.DOTALL
);
```

**Bing 搜索结果的 HTML 结构：**

```
<li class="b_algo">
  <h2><a href="https://example.com">标题</a></h2>
  <div class="b_caption">
    <p>摘要内容...</p>
  </div>
</li>
```

**用正则匹配：**

1. 先匹配每个 `<li class="b_algo">` 结果项
2. 再从结果项里提取标题、链接、摘要

**为什么用正则不用 HTML 解析库？**

- 简单，不需要额外依赖（jsoup 等）
- 只需要提取几个固定元素，正则够用
- 缺点是脆弱，Bing 改版就失效
- 但作为备胎，能用就行，主通道是 API

#### 4. Pattern.DOTALL

```
Pattern.compile("...", Pattern.DOTALL)
```

**DOTALL 模式：** `.` 匹配包括换行符在内的所有字符。

HTML 元素通常跨多行，没有 DOTALL 的话，`.*?` 匹配不到跨行内容。

#### 5. 去 HTML 标签和实体

```
private String stripHtml(String html) {
    return html.replaceAll("<[^>]+>", "")
               .replaceAll("&nbsp;", " ")
               .replaceAll("&amp;", "&")
               .replaceAll("&lt;", "<")
               .replaceAll("&gt;", ">")
               .replaceAll("&quot;", "\"")
               .trim();
}
```

提取的标题和摘要里可能有 HTML 标签和实体，要清理掉。

```
    │   ├─ 是 → 尝试 GlmSearchClient.search()
    │   │   ├─ 构建请求（search_query, search_pro, count）
    │   │   ├─ POST 到 GLM API
    │   │   ├─ 成功？
    │   │   │   ├─ 是 → 解析 JSON → 格式化结果 → 返回
    │   │   │   └─ 否（超时/余额不足/错误）→ catch 异常
    │   │   │       └─ 降级到 BingHtmlSearch
    │   │   └─ 返回结果
    │   └─ 否 → 直接 BingHtmlSearch
    │
    ▼
BingHtmlSearch.search()
    ├─ URL 编码关键词
    ├─ GET cn.bing.com/search?q=...
    ├─ 伪装 User-Agent
    ├─ 解析 HTML（正则匹配 b_algo）
    ├─ 提取标题/链接/摘要
    └─ 格式化返回
    │
    ▼
返回统一格式的搜索结果给 AI
    │
    ▼
AI 整理搜索结果，给出回复
```

## 常见坑（详细版）

### 1. Bing 地区限制

**现象：** `www.bing.com` 访问超时或被重定向。

**原因：** 国际版 Bing 在国内访问不稳定。

**解决：**

- 用 `cn.bing.com`，国内直连
- 或者用户自己配置代理
- 我们默认用 [cn.bing.com](https://link.wtturl.cn/?target=https%3A%2F%2Fcn.bing.com&scene=im&aid=497858&lang=zh)，国内用户友好

### 2. GLM 余额不足

**现象：** API 返回 402 错误，搜索失败。

**原因：** API key 余额用完了。

**解决：**

- catch 异常，自动降级到 HTML
- 用户无感，搜索还能用
- 可以在日志里提醒用户充值
- 双通道设计就是为了这种情况

### 3. HTML 解析脆弱

**现象：** Bing 改版后，搜索结果为空或解析错误。

**原因：** 正则依赖 Bing 的 HTML 结构，改版后 class 名或结构变了。

**解决：**

- 这是 HTML 抓取的固有问题
- 双通道设计：API 是主通道，HTML 只是备胎
- API 正常的话，用户不会遇到这个问题
- HTML 解析失效了，更新正则就行
- 或者换用 jsoup 等 HTML 解析库，更健壮

### 4. 搜索结果占 token

**现象：** 搜索结果太长，加上历史消息超 token 窗口。

**原因：** 每条结果的摘要可能很长，5 条加起来就很多了。

**解决：**

- 摘要截断到 200-300 字符
- 默认只返回 5 条，最多 10 条
- 配合第 15 章的上下文压缩，大结果存盘
- AI 需要详细内容可以用 read_file 或自己访问链接

### 5. 搜索关键词不精准

**现象：** AI 搜的关键词不对，结果不相关。

**原因：** AI 可能用自然语言当关键词，而不是精准的搜索词。

**解决：**

- 工具 description 里说明 "搜索关键词"
- 或者加一个 `search_intent: true` 参数，让 GLM API 先理解意图
- AI 用多了就会学会用精准的关键词

### 6. URL 编码问题

**现象：** 中文关键词搜索，结果乱码或搜不到。

**原因：** 关键词没做 URL 编码，中文直接拼到 URL 里。

**解决：**

```
URLEncoder.encode(query, StandardCharsets.UTF_8)
```

- 必须用 UTF-8 编码
- 空格变成 `+`，特殊字符变成 `%XX`

### 7. Bing 反爬

**现象：** 频繁搜索后，Bing 返回验证码页面。

**原因：** Bing 检测到异常访问，要求验证。

**解决：**

- 不要太频繁调用（加间隔或缓存）
- 伪装 User-Agent（我们已经做了）
- 加请求间隔，避免短时间大量请求
- 真遇到了，等一会再试，或者用 API 通道

### 8. API 和 HTML 结果质量差异

**现象：** HTML 通道的结果质量比 API 差。

**原因：**

- API 返回的是结构化的、有摘要的结果
- HTML 只能提取标题和简短摘要
- HTML 可能有广告、无关结果

**解决：**

- 这是正常的，备胎肯定不如主通道
- 有 API key 就用 API
- HTML 只是保证 "能用"，不保证 "最好"

## 双通道对比总结

|  维度  |    GLM API（主通道）     |      Bing HTML（备胎）      |
| :----: | :----------------------: | :-------------------------: |
|  质量  |   高（结构化、有摘要）   | 中（只能提取标题 + 短摘要） |
|  中文  | 好（智谱国产，中文优化） |   一般（cn.bing 还可以）    |
|  成本  |     付费（单独计费）     |            免费             |
|  配置  |       需要 API key       |           零配置            |
| 稳定性 |      依赖 API 服务       |     依赖 Bing 页面结构      |
|  速度  |   快（直接返回 JSON）    | 中等（要下载 + 解析 HTML）  |
|  适用  |     有 key、追求质量     |      没 key、API 挂了       |

**双通道设计：有 key 用最好的，没 key 也能用，API 挂了自动切。**
