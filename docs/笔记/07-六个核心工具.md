# 07 — 六个核心工具

## 这一章做什么

实现六个最核心的内置工具：**ReadFile、WriteFile、EditFile、ExecCommand、Glob、Grep**。

**完成后 AI 能做到：**

- 读文件内容
- 创建 / 覆盖写文件
- 精确修改文件的某一段
- 执行 shell 命令
- 按文件名模式搜索文件
- 在文件里搜索内容

**从此 AI 从 "聊天机器人" 变成 "编程助手"**—— 它能真的操作你的文件系统、跑命令了。

## 为什么需要

纯对话的 AI 只能 "说"，不能 "做"。

**没有工具的 AI：**

- 你问 "这个文件里有什么" → 它只能猜
- 你说 "帮我改一下代码" → 它只能给你代码片段，你自己复制粘贴
- 你说 "跑一下测试" → 它做不到

**有了这六个工具的 AI：**

- 你问 "这个文件里有什么" → 它调用 read_file 读给你看
- 你说 "帮我改一下代码" → 它调用 edit_file 直接改
- 你说 "跑一下测试" → 它调用 exec_command 跑 mvn test

**这就是 Agent 的核心能力：行动。**

## 核心概念

|        工具         |   作用   |            核心技术            |
| :-----------------: | :------: | :----------------------------: |
|  **ReadFileTool**   |  读文件  | `Files.readString()`，支持截断 |
|  **WriteFileTool**  |  写文件  | 临时文件 + 原子移动，防止写坏  |
|  **EditFileTool**   |  改文件  |  精确字符串匹配替换，只改一处  |
| **ExecCommandTool** | 执行命令 |  `ProcessBuilder` + 超时保护   |
|    **GlobTool**     | 文件搜索 | `PathMatcher` + `Files.walk()` |
|    **GrepTool**     | 内容搜索 |       正则表达式逐行匹配       |

## ReadFileTool

最基础的工具，读取文件内容。

```java
// tools/impl/ReadFileTool.java
package com.rook.tools.impl;

import com.rook.tools.Tool;
import com.rook.tools.ToolResult;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.*;

public class ReadFileTool implements Tool {

    // 最大读取 100KB，防止大文件撑爆上下文
    private static final int MAX_BYTES = 100 * 1024;

    @Override 
    public String name() { return "read_file"; }

    @Override 
    public String description() {
        return "读取指定文件的内容。用于查看源代码、配置文件、文档等文本文件。" +
               "支持指定起始行和行数来读取部分内容。大文件会自动截断。";
    }

    @Override
    public Map<String, Object> inputSchema() {
        return Map.of(
            "type", "object",
            "properties", Map.of(
                "filePath", Map.of(
                    "type", "string", 
                    "description", "要读取的文件路径"
                ),
                "offset", Map.of(
                    "type", "integer", 
                    "description", "起始行号，从 0 开始（可选）"
                ),
                "limit", Map.of(
                    "type", "integer", 
                    "description", "读取多少行（可选）"
                )
            ),
            "required", List.of("filePath")
        );
    }

    @Override
    public ToolResult execute(Map<String, Object> params) {
        // 1. 参数校验
        String path = (String) params.get("filePath");
        if (path == null || path.isBlank()) {
            return ToolResult.error("缺少必填参数: filePath");
        }

        // 2. 检查文件是否存在
        Path file = Path.of(path);
        if (!Files.exists(file)) {
            return ToolResult.error("文件不存在: " + path);
        }

        try {
            // 3. 读取文件内容
            String content = Files.readString(file);
            
            // 4. 大文件截断
            if (content.getBytes().length > MAX_BYTES) {
                content = new String(content.getBytes(), 0, MAX_BYTES) 
                    + "\n...(文件过大，已截断)";
            }
            
            return ToolResult.ok(content);
        } catch (IOException e) {
            return ToolResult.error("读取文件失败: " + e.getMessage());
        }
    }
}
```

### 逐段详解

#### 1. MAX_BYTES 截断

```
private static final int MAX_BYTES = 100 * 1024; // 100KB
```

**为什么要截断？**

- LLM 的上下文窗口是有限的
- 如果用户让读一个 10MB 的日志文件，全读进去会撑爆上下文
- 截断到 100KB，既够用又安全

**为什么按字节算不是按字符算？**

- 中文一个字符占多个字节
- 按字节算更准确，不会超出预期

**截断后怎么办？**

- 告诉 AI 文件被截断了
- AI 可以用 offset/limit 分段读取（后面可以加这个功能）

#### 2. 参数校验

```
String path = (String) params.get("filePath");
if (path == null || path.isBlank()) {
    return ToolResult.error("缺少必填参数: filePath");
}
```

**为什么要校验？**

- LLM 有时候会漏传参数
- 不校验的话后面会 NullPointerException
- 给出清晰的错误信息，LLM 可能自己纠正

#### 3. 检查文件存在

```
Path file = Path.of(path);
if (!Files.exists(file)) {
    return ToolResult.error("文件不存在: " + path);
}
```

文件不存在就直接返回错误，不用往下走了。

#### 4. 读取文件

```
String content = Files.readString(file);
```

Java 11+ 的方法，一行就读完整个文件。

**底层做了什么？**

- 打开文件
- 全部读进内存
- 用 UTF-8 解码成字符串
- 自动关闭文件

------

5. #### JSON

```json
{
  "type": "object",
  "properties": {
    "filePath": {"type": "string", "description": "要读取的文件路径"},
    "offset": {"type": "integer", "description": "起始行号，从 0 开始（可选）"},
    "limit": {"type": "integer", "description": "读取多少行（可选）"}
  },

}
```

## WriteFileTool（原子写入）

写文件，支持创建新文件和覆盖已有文件。

**亮点：原子写入**—— 要么全部写成功，要么保持原样，不会出现 "写了一半" 的损坏文件。

```java
// tools/impl/WriteFileTool.java
package com.rook.tools.impl;

import com.rook.tools.Tool;
import com.rook.tools.ToolResult;

import java.io.IOException;
import java.nio.file.*;
import java.util.*;

public class WriteFileTool implements Tool {

    @Override 
    public String name() { return "write_file"; }

    @Override 
    public String description() {
        return "创建或覆盖写入文件。用于创建新文件、保存代码、写入配置等。" +
               "写入是原子的，不会出现半写的损坏文件。";
    }

    @Override
    public Map<String, Object> inputSchema() {
        return Map.of(
            "type", "object",
            "properties", Map.of(
                "filePath", Map.of(
                    "type", "string", 
                    "description", "要写入的文件路径"
                ),
                "content", Map.of(
                    "type", "string", 
                    "description", "文件内容"
                )
            ),
            "required", List.of("filePath", "content")
        );
    }

    @Override
    public ToolResult execute(Map<String, Object> params) {
        String path = (String) params.get("filePath");
        String content = (String) params.get("content");
        
        if (path == null || path.isBlank()) {
            return ToolResult.error("缺少参数: filePath");
        }
        if (content == null) {
            return ToolResult.error("缺少参数: content");
        }

        try {
            Path target = Path.of(path);
            
            // 确保父目录存在
            if (target.getParent() != null) {
                Files.createDirectories(target.getParent());
            }

            // ★ 原子写入：先写 .tmp 临时文件，再原子重命名
            Path tmp = target.resolveSibling(target.getFileName() + ".tmp");
            Files.writeString(tmp, content);
            
            // 原子移动：tmp → 目标文件
            Files.move(tmp, target, 
                StandardCopyOption.ATOMIC_MOVE,
                StandardCopyOption.REPLACE_EXISTING);
            
            return ToolResult.ok("已写入文件: " + path);
        } catch (IOException e) {
            return ToolResult.error("写入文件失败: " + e.getMessage());
        }
    }
}
```

### 逐段详解

#### 1. 为什么需要原子写入？

**想象一下：直接写文件，写到一半程序崩了。**

```
原文件内容：完整的代码
         ↓
    开始写入
         ↓
    写了一半... 崩了！
         ↓
结果：文件里只有一半内容，原内容也没了 → 文件损坏
```

**用户的代码就没了，这是灾难。**

#### 2. 原子写入的原理

```
1. 先写到临时文件 config.yaml.tmp
   （这时候原文件 config.yaml 还是完好的）
   
2. 临时文件写成功了 → 原子重命名
   config.yaml.tmp → config.yaml
   
3. 重命名是原子操作：要么成功，要么失败
   成功 → 新文件就位
   失败 → 原文件还在，什么都没变
```

**关键点：重命名（move）是原子操作。**

- 在同一个文件系统上，重命名是瞬间完成的
- 不会出现 "正在重命名" 的中间状态
- 要么成功，要么失败，没有中间态

#### 3. 代码实现

```
// 临时文件路径：和目标文件同目录，文件名加 .tmp 后缀
Path tmp = target.resolveSibling(target.getFileName() + ".tmp");
```

`resolveSibling()` 是什么？

- 在目标文件的同级目录下，创建一个新路径
- 比如目标是 `/a/b/c.txt`，`resolveSibling("c.txt.tmp")` 得到 `/a/b/c.txt.tmp`

```
// 写到临时文件
Files.writeString(tmp, content);

// 原子移动
Files.move(tmp, target, 
    StandardCopyOption.ATOMIC_MOVE,       // 原子操作
    StandardCopyOption.REPLACE_EXISTING); // 目标存在就覆盖
```

**两个选项：**

- `ATOMIC_MOVE` — 要求原子移动，做不到就抛异常
- `REPLACE_EXISTING` — 目标文件存在就覆盖

## EditFileTool（唯一匹配替换）

精确修改文件的某一段内容。

**亮点：唯一匹配**—— 必须精确匹配到一处才替换，匹配 0 处或多处都报错，防止改错地方。

```java
// tools/impl/EditFileTool.java
package com.rook.tools.impl;

import com.rook.tools.Tool;
import com.rook.tools.ToolResult;

import java.io.IOException;
import java.nio.file.*;
import java.util.*;

public class EditFileTool implements Tool {

    @Override 
    public String name() { return "edit_file"; }

    @Override 
    public String description() {
        return "精确修改文件中的一段内容。需要提供要替换的原文和新内容。" +
               "原文必须在文件中唯一匹配（只出现一次），否则会报错。" +
               "用于修改代码、更新配置等精确编辑场景。";
    }

    @Override
    public Map<String, Object> inputSchema() {
        return Map.of(
            "type", "object",
            "properties", Map.of(
                "filePath", Map.of(
                    "type", "string", 
                    "description", "要修改的文件路径"
                ),
                "oldString", Map.of(
                    "type", "string", 
                    "description", "要替换的原文（必须精确匹配，包括空格换行）"
                ),
                "newString", Map.of(
                    "type", "string", 
                    "description", "新内容"
                )
            ),
            "required", List.of("filePath", "oldString", "newString")
        );
    }

    @Override
    public ToolResult execute(Map<String, Object> params) {
        String path = (String) params.get("filePath");
        String oldStr = (String) params.get("oldString");
        String newStr = (String) params.get("newString");

        if (path == null || oldStr == null || newStr == null) {
            return ToolResult.error("缺少必填参数");
        }

        try {
            // 1. 读取整个文件
            String content = Files.readString(Path.of(path));

            // 2. 统计 oldString 出现了几次
            int count = 0;
            int idx = 0;
            int lastIdx = -1;
            while ((idx = content.indexOf(oldStr, idx)) != -1) {
                count++;
                lastIdx = idx;
                idx += oldStr.length();
            }

            // 3. 匹配 0 次 → 报错
            if (count == 0) {
                return ToolResult.error("未找到匹配的原文片段，请确认内容是否正确");
            }

            // 4. 匹配多次 → 报错，让 AI 提供更精确的上下文
            if (count > 1) {
                return ToolResult.error(
                    "匹配到 " + count + " 处，不唯一。" +
                    "请提供更多上下文（包含更多前后行），确保唯一匹配。"
                );
            }

            // 5. 唯一匹配 → 替换
            String newContent = content.substring(0, lastIdx) + newStr
                + content.substring(lastIdx + oldStr.length());

            // 6. 复用 WriteFileTool 写回去（原子写入）
            WriteFileTool wf = new WriteFileTool();
            return wf.execute(Map.of("filePath", path, "content", newContent));

        } catch (IOException e) {
            return ToolResult.error("修改文件失败: " + e.getMessage());
        }
    }
}
```

### 逐段详解

#### 1. 为什么要 "唯一匹配"？

**想象一下：文件里有 5 处相同的代码，你只想改其中一处。**

如果直接全部替换：

```
content.replace(oldStr, newStr)  // 全部替换，5 处都改了
```

→ 可能改错地方，把不该改的也改了。

**唯一匹配的设计：**

- 只出现 1 次 → 安全替换
- 出现 0 次 → 报错，让 AI 检查是不是写错了
- 出现多次 → 报错，让 AI 提供更多上下文

**这是一种安全机制，防止 AI 改错文件。**

#### 2. 统计匹配次数

```java
int count = 0;
int idx = 0;
int lastIdx = -1;
while ((idx = content.indexOf(oldStr, idx)) != -1) {
    count++;
    lastIdx = idx;      // 记录最后一次匹配的位置
    idx += oldStr.length();
}
```

**逻辑：**

- 从前往后找
- 找到一次 count+1
- 记录最后一次匹配的位置（后面替换要用）
- 继续从匹配位置的后面找

#### 3. 替换

```java
String newContent = content.substring(0, lastIdx) + newStr
    + content.substring(lastIdx + oldStr.length());
```

**三段拼接：**

- 匹配位置之前的内容 → 原样保留
- 新字符串 → 替换进去
- 匹配位置之后的内容 → 原样保留

```
[...之前的内容...] oldStr [...之后的内容...]
           ↓
[...之前的内容...] newStr [...之后的内容...]
```

#### 4. 复用 WriteFileTool

```
WriteFileTool wf = new WriteFileTool();
return wf.execute(Map.of("filePath", path, "content", newContent));
```

改完之后，用 WriteFileTool 写回去。

**为什么复用？**

- 不用重复写原子写入的逻辑
- 保持一致的安全性
- 代码复用

## ExecCommandTool（带超时）

执行 shell 命令。

**亮点：超时保护**——30 秒硬限制，防止命令卡死整个程序。

```java
// tools/impl/ExecCommandTool.java
package com.rook.tools.impl;

import com.rook.tools.Tool;
import com.rook.tools.ToolResult;

import java.io.IOException;
import java.util.Map;
import java.util.concurrent.TimeUnit;

public class ExecCommandTool implements Tool {

    private static final int TIMEOUT_SECONDS = 30;

    @Override 
    public String name() { return "exec_command"; }

    @Override 
    public String description() {
        return "执行 shell 命令并返回输出。用于运行测试、构建项目、查看目录、" +
               "执行 git 命令等。命令有 30 秒超时限制，超时会被强制终止。";
    }

    @Override
    public Map<String, Object> inputSchema() {
        return Map.of(
            "type", "object",
            "properties", Map.of(
                "command", Map.of(
                    "type", "string", 
                    "description", "要执行的 shell 命令"
                )
            ),
            "required", List.of("command")
        );
    }

    @Override
    public ToolResult execute(Map<String, Object> params) {
        String cmd = (String) params.get("command");
        if (cmd == null || cmd.isBlank()) {
            return ToolResult.error("缺少参数: command");
        }

        // 判断操作系统，Windows 用 cmd，其他用 sh
        boolean isWindows = System.getProperty("os.name")
            .toLowerCase().contains("win");

        // 构建进程
        ProcessBuilder pb = new ProcessBuilder(
            isWindows ? "cmd" : "sh",
            isWindows ? "/c" : "-c",
            cmd
        );

        try {
            // 启动进程
            Process p = pb.start();

            // 等待完成，最多等 30 秒
            boolean finished = p.waitFor(TIMEOUT_SECONDS, TimeUnit.SECONDS);

            // 超时了 → 强制杀掉
            if (!finished) {
                p.destroyForcibly();
                return ToolResult.error("命令执行超时（" + TIMEOUT_SECONDS + "秒），已强制终止");
            }

            // 读取标准输出和标准错误
            String stdout = new String(p.getInputStream().readAllBytes());
            String stderr = new String(p.getErrorStream().readAllBytes());

            // 返回退出码 + 输出
            return ToolResult.ok(
                "exit code: " + p.exitValue() + "\n" +
                "--- stdout ---\n" + stdout +
                "--- stderr ---\n" + stderr
            );

        } catch (IOException | InterruptedException e) {
            if (e instanceof InterruptedException) {
                Thread.currentThread().interrupt();
            }
            return ToolResult.error("执行命令失败: " + e.getMessage());
        }
    }
}
```

### 逐段详解

#### 1. 为什么需要 ProcessBuilder？

Java 里执行外部命令的标准方式。

**两种方式：**

- `Runtime.getRuntime().exec()` — 老方式，不推荐
- `new ProcessBuilder().start()` — 新方式，更灵活

**ProcessBuilder 能做什么？**

- 设置命令和参数
- 设置工作目录
- 设置环境变量
- 重定向输入输出
- 启动进程

#### 2. 跨平台处理

```java
boolean isWindows = System.getProperty("os.name")
    .toLowerCase().contains("win");

ProcessBuilder pb = new ProcessBuilder(
    isWindows ? "cmd" : "sh",    // Windows 用 cmd，其他用 sh
    isWindows ? "/c" : "-c",     // /c 或 -c 表示执行后面的命令
    cmd
);
```

**为什么要套一层 cmd/sh？**

因为用户输入的是完整的命令字符串，比如 `ls -la | grep java`，里面有管道、重定向这些 shell 语法。

- 直接执行 `ls -la | grep java` → 不行，因为 `|` 是 shell 的语法
- 用 `sh -c "ls -la | grep java"` → 让 shell 来解析命令

**Windows 上用 cmd /c，Linux/macOS 上用 sh -c。**

#### 3. 超时保护

```java
boolean finished = p.waitFor(TIMEOUT_SECONDS, TimeUnit.SECONDS);

if (!finished) {
    p.destroyForcibly();
    return ToolResult.error("命令超时，已强制终止");
}
```

**为什么需要超时？**

- 用户可能让 AI 跑一个死循环
- 某些命令可能卡住（比如等待输入）
- 没有超时的话，整个程序就卡死了

**`waitFor(30, SECONDS)` 做了什么？**

- 等待进程结束
- 最多等 30 秒
- 30 秒内结束了 → 返回 true
- 30 秒还没结束 → 返回 false，进程还在跑

**`destroyForcibly()` 做了什么？**

- 强制杀掉进程
- 相当于 Linux 的 `kill -9`

#### 4. 读取输出

```java
String stdout = new String(p.getInputStream().readAllBytes());
String stderr = new String(p.getErrorStream().readAllBytes());
```

**两个输出流：**

- `getInputStream()` — 标准输出（stdout）
- `getErrorStream()` — 标准错误（stderr）

**为什么要分开？**

- 正常输出和错误信息是分开的
- 有些命令正常输出和错误输出混在一起，分开更清楚

**`readAllBytes()` 是什么？**

Java 9+ 的方法，一次性读完整个流的所有字节。

## GlobTool

按文件名模式搜索文件，比如 `**/*.java` 找出所有 Java 文件。

```java
// tools/impl/GlobTool.java
package com.rook.tools.impl;

import com.rook.tools.Tool;
import com.rook.tools.ToolResult;

import java.io.IOException;
import java.nio.file.*;
import java.util.*;
import java.util.stream.Collectors;

public class GlobTool implements Tool {

    @Override 
    public String name() { return "glob"; }

    @Override 
    public String description() {
        return "按文件名模式搜索文件。支持 glob 模式匹配，如 **/*.java（所有Java文件）、" +
               "src/**/*.ts（src下所有TypeScript文件）等。返回匹配的文件路径列表。";
    }

    @Override
    public Map<String, Object> inputSchema() {
        return Map.of(
            "type", "object",
            "properties", Map.of(
                "pattern", Map.of(
                    "type", "string", 
                    "description", "glob 模式，如 **/*.java"
                ),
                "basePath", Map.of(
                    "type", "string", 
                    "description", "搜索的起始目录（可选，默认当前目录）"
                )
            ),
            "required", List.of("pattern")
        );
    }

    @Override
    public ToolResult execute(Map<String, Object> params) {
        String pattern = (String) params.get("pattern");
        String basePathStr = (String) params.getOrDefault("basePath", ".");

        if (pattern == null || pattern.isBlank()) {
            return ToolResult.error("缺少参数: pattern");
        }

        try {
            Path basePath = Path.of(basePathStr);
            if (!Files.isDirectory(basePath)) {
                return ToolResult.error("起始目录不存在: " + basePathStr);
            }

            // 创建 PathMatcher
            PathMatcher matcher = FileSystems.getDefault()
                .getPathMatcher("glob:" + pattern);

            // 遍历目录树，收集匹配的文件
            List<String> matches = Files.walk(basePath)
                .filter(Files::isRegularFile)
                .filter(matcher::matches)
                .map(p -> basePath.relativize(p).toString())
                .sorted()
                .collect(Collectors.toList());

            if (matches.isEmpty()) {
                return ToolResult.ok("没有找到匹配的文件");
            }

            return ToolResult.ok("找到 " + matches.size() + " 个文件:\n" +
                String.join("\n", matches));

        } catch (IOException e) {
            return ToolResult.error("搜索失败: " + e.getMessage());
        }
    }
}
```

### 逐段详解

#### 1. 什么是 Glob？

一种文件名匹配模式，比正则简单，常用在 shell 里。

**常见模式：**

|     模式      |           含义            |               示例                |
| :-----------: | :-----------------------: | :-------------------------------: |
|   `*.java`    | 当前目录下所有 .java 文件 |     `Main.java`、`Util.java`      |
|  `**/*.java`  | 所有子目录下的 .java 文件 | `src/Main.java`、`test/Test.java` |
| `src/**/*.ts` |  src 目录下所有 .ts 文件  |         `src/app/App.ts`          |
| `*.{java,kt}` |     .java 或 .kt 文件     |       `Main.java`、`App.kt`       |
| `Test?.java`  |    Test 后面跟一个字符    |    `Test1.java`、`TestA.java`     |

**`\**` 表示任意层级的子目录。**

#### 2. PathMatcher

```
PathMatcher matcher = FileSystems.getDefault()
    .getPathMatcher("glob:" + pattern);
```

Java NIO 的文件路径匹配器。

**两种语法：**

- `glob:` — glob 模式（简单，常用）
- `regex:` — 正则表达式（复杂，强大）

我们用 glob 就够了。

#### 3. 遍历目录树

```java
List<String> matches = Files.walk(basePath)
    .filter(Files::isRegularFile)      // 只要文件，不要目录
    .filter(matcher::matches)          // 匹配模式
    .map(p -> basePath.relativize(p).toString())  // 转成相对路径
    .sorted()                          // 排序
    .collect(Collectors.toList());
```

**`Files.walk()` 是什么？**

递归遍历目录树，返回一个 Stream<Path>，包含所有子目录和文件。

**链式操作：**

1. `walk(basePath)` — 遍历所有路径
2. `filter(Files::isRegularFile)` — 只留文件，过滤掉目录
3. `filter(matcher::matches)` — 只留匹配模式的
4. `map(...)` — 转成相对路径字符串
5. `sorted()` — 排序
6. `collect(toList())` — 收集成列表

## GrepTool

在文件里搜索内容，类似 Linux 的 grep 命令。

```java
// tools/impl/GrepTool.java
package com.rook.tools.impl;

import com.rook.tools.Tool;
import com.rook.tools.ToolResult;

import java.io.IOException;
import java.nio.file.*;
import java.util.*;
import java.util.regex.*;
import java.util.stream.Collectors;

public class GrepTool implements Tool {

    @Override 
    public String name() { return "grep"; }

    @Override 
    public String description() {
        return "在文件中搜索内容，支持正则表达式。类似 grep 命令。" +
               "可以指定文件名过滤，只在匹配的文件中搜索。返回匹配的行及行号。";
    }

    @Override
    public Map<String, Object> inputSchema() {
        return Map.of(
            "type", "object",
            "properties", Map.of(
                "pattern", Map.of(
                    "type", "string", 
                    "description", "搜索模式（正则表达式）"
                ),
                "filePattern", Map.of(
                    "type", "string", 
                    "description", "文件名过滤 glob 模式（可选，默认所有文件）"
                ),
                "basePath", Map.of(
                    "type", "string", 
                    "description", "搜索起始目录（可选，默认当前目录）"
                )
            ),
            "required", List.of("pattern")
        );
    }

    @Override
    public ToolResult execute(Map<String, Object> params) {
        String patternStr = (String) params.get("pattern");
        String filePattern = (String) params.get("filePattern");
        String basePathStr = (String) params.getOrDefault("basePath", ".");

        if (patternStr == null || patternStr.isBlank()) {
            return ToolResult.error("缺少参数: pattern");
        }

        try {
            Pattern pattern = Pattern.compile(patternStr);
            Path basePath = Path.of(basePathStr);

            // 先找出所有要搜索的文件
            List<Path> files;
            if (filePattern != null && !filePattern.isBlank()) {
                PathMatcher matcher = FileSystems.getDefault()
                    .getPathMatcher("glob:" + filePattern);
                files = Files.walk(basePath)
                    .filter(Files::isRegularFile)
                    .filter(matcher::matches)
                    .collect(Collectors.toList());
            } else {
                files = Files.walk(basePath)
                    .filter(Files::isRegularFile)
                    .collect(Collectors.toList());
            }

            // 在每个文件里搜索
            StringBuilder result = new StringBuilder();
            int totalMatches = 0;

            for (Path file : files) {
                List<String> lines = Files.readAllLines(file);
                List<String> matchedLines = new ArrayList<>();

                for (int i = 0; i < lines.size(); i++) {
                    if (pattern.matcher(lines.get(i)).find()) {
                        matchedLines.add((i + 1) + ": " + lines.get(i));
                    }
                }

                if (!matchedLines.isEmpty()) {
                    result.append("--- ").append(basePath.relativize(file)).append(" ---\n");
                    matchedLines.forEach(line -> result.append(line).append("\n"));
                    totalMatches += matchedLines.size();
                }
            }

            if (totalMatches == 0) {
                return ToolResult.ok("没有找到匹配的内容");
            }

            return ToolResult.ok("找到 " + totalMatches + " 处匹配:\n" + result);

        } catch (PatternSyntaxException e) {
            return ToolResult.error("正则表达式语法错误: " + e.getMessage());
        } catch (IOException e) {
            return ToolResult.error("搜索失败: " + e.getMessage());
        }
    }
}
```

### 逐段详解

#### 1. 什么是 Grep？

Global Regular Expression Print 的缩写，Unix 里最常用的搜索工具。

**作用：** 在文件里找包含特定内容的行。

**示例：**

```
grep "public class" *.java
```

找出所有 Java 文件里包含 "public class" 的行。

#### 2. 正则表达式

```
Pattern pattern = Pattern.compile(patternStr);
```

用正则表达式匹配，比普通字符串搜索强大。

**常用正则：**

|      模式       |              含义              |
| :-------------: | :----------------------------: |
| `public.*class` | public 和 class 之间有任意字符 |
|    `^import`    |       以 import 开头的行       |
|      `;$`       |         以分号结尾的行         |
|      `\d+`      |         一个或多个数字         |

#### 3. 搜索流程

```
1. 找出所有要搜索的文件
   （可以用 filePattern 过滤）
   ↓
2. 逐个文件读取
   ↓
3. 逐行匹配正则
   ↓
4. 收集匹配的行（带行号）
   ↓
5. 输出结果
```

#### 4. 为什么要文件名过滤？

如果只在 Java 文件里搜，就不用搜 .class 文件、.git 目录等，更快更准。

## 常见坑（详细版）

### 1. EditFileTool 的 oldString 必须精确

**现象：** 总是报 "未找到匹配的原文片段"。

**原因：** oldString 必须精确匹配，包括：

- 空格
- Tab
- 换行
- 缩进

**LLM 容易搞错的地方：**

- 缩进是空格还是 Tab？
- 每行末尾有没有空格？
- 换行是 `\n` 还是 `\r\n`？

**解决：**

- 让 AI 先用 read_file 看一下文件内容
- 再用看到的精确内容来 edit
- 如果匹配多次，让 AI 提供更多上下文（包含前后行）

### 2. ExecCommandTool 的超时

**现象：** 长时间运行的命令（比如 `mvn package`）总是超时。

**原因：** 30 秒硬限制，防止命令卡死。

**30 秒够吗？**

- 大部分命令（ls、cat、git status）几秒就完了
- 编译、测试可能需要更久
- 可以根据需要调整超时时间

**`destroyForcibly()` 的问题：**

- 强制杀掉进程
- 但子进程可能残留（比如进程又 fork 了子进程）
- Windows 上可能杀不干净

**以后可以优化：**

- 可配置的超时时间
- 支持后台运行，异步查看结果
- 进程组管理，确保子进程也被杀掉

### 3. WriteFileTool 原子写入的限制

**现象：** 跨磁盘写入时报错。

**原因：** `ATOMIC_MOVE` 要求源和目标在同一个文件系统上。

**什么情况会跨盘？**

- 临时文件在 C 盘，目标在 D 盘
- 临时文件在本地磁盘，目标在网络盘

**解决：**

- 临时文件和目标文件放在同一目录（我们的实现就是这样的，所以一般不会有问题）
- 如果跨盘，ATOMIC_MOVE 会抛异常，可以降级为普通 move

### 4. 路径安全问题

**现象：** AI 可能读取 / 修改系统关键文件。

**风险：**

- 读 `/etc/passwd`
- 删系统文件
- 执行危险命令

**现在的实现：** 没有限制，AI 想干嘛干嘛。

**以后可以加的安全措施：**

- 工作目录限制：只能操作当前目录下的文件
- 路径白名单 / 黑名单
- 危险命令确认（比如 rm -rf）
- 沙箱环境

### 5. 大文件问题

**现象：** 读大文件很慢，或者撑爆上下文。

**现在的处理：**

- ReadFileTool 截断到 100KB
- GrepTool 读整个文件到内存

**以后可以优化：**

- 流式读取，不全部加载到内存
- 分页读取（offset + limit）
- 结果也限制最大行数

### 6. 编码问题

**现象：** 读非 UTF-8 编码的文件乱码。

**原因：** `Files.readString()` 默认用 UTF-8。

**解决：**

- 可以加参数指定编码
- 或者自动检测编码
- 但大部分情况 UTF-8 就够了
