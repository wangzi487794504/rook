# 17 — 会话存档与恢复

## 这一章做什么

用 **JSONL 格式**持久化对话历史。崩溃只丢最后一行，恢复时跳过坏行，30 天自动清理。

**完成后你能做到：**

- 程序崩溃了？重启恢复，只丢最后一条消息
- 文件损坏了？自动跳过坏行，不崩溃
- 聊了一半有事走了？下次打开继续聊
- 30 天前的旧会话？自动清理，不占磁盘

## 为什么需要

### 旧方式的问题

之前的 `Session.save()` 用 Jackson 写整个 JSON 数组：

```
// 旧方式
List<ChatMessage> history = ...;
String json = mapper.writerWithDefaultPrettyPrinter().writeValueAsString(history);
Files.writeString(file, json);  // 整个文件重写
```

**问题：**

|       问题        |                        说明                         |
| :---------------: | :-------------------------------------------------: |
| 写一半崩溃 → 全丢 | 整个文件重写，写到一半断电，文件损坏，全部历史没了  |
|  每次全量写 → 慢  | 1000 条消息，每次保存都要序列化 1000 条，写整个文件 |
| 一条坏数据 → 全丢 |        反序列化时一条出错，整个文件解析失败         |
| 大文件 → 内存压力 |         读整个文件到内存，历史越长越占内存          |

### JSONL 的优势

JSONL（JSON Lines）：**每行一个独立的 JSON 对象**。

```
{"role":"user","content":"你好","timestamp":"2026-08-13T10:00:00"}
{"role":"assistant","content":"你好！有什么可以帮你？","timestamp":"2026-08-13T10:00:01"}
{"role":"user","content":"帮我读个文件","timestamp":"2026-08-13T10:01:00"}
```

**优势：**

|       优势       |                     说明                     |
| :--------------: | :------------------------------------------: |
|   追加写 O (1)   |       新消息只写一行，不用重写整个文件       |
| 崩溃只丢最后一行 | 写到一半崩溃，最多最后一行不完整，前面的都在 |
|     坏行跳过     |      某一行损坏，跳过就行，不影响其他行      |
|     流式读取     |        逐行读，不用一次性加载整个文件        |

## 核心概念

### JSONL 格式

- 每行一个独立的 JSON 对象
- 不能格式化（不能有换行缩进）
- 用换行符分隔
- 追加写，不重写

### 恢复容错

- 逐行读取
- JSON 解析异常的行跳过，不崩溃
- 最后一条不完整的消息截断

### 时间跨度提醒

- 恢复时，在间隔 > 1 小时的消息间插入 `[N 小时前]` 提示
- 让 AI 知道这是隔了一段时间的对话，上下文可能不连续

### 自动清理

- 30 天前的会话文件自动删除
- 防止磁盘被旧会话占满

## 第一步：JSONL 追加写入

```
// memory/SessionArchiver.java
package com.rook.memory;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.SerializationFeature;
import com.rook.llm.ChatMessage;
import java.io.*;
import java.nio.file.*;
import java.time.Instant;
import java.util.*;

public class SessionArchiver {

    // 注意：不启用 pretty print，否则一行变多行
    private static final ObjectMapper MAPPER = new ObjectMapper()
        .disable(SerializationFeature.INDENT_OUTPUT);

    /**
     * 追加一条消息到 JSONL 文件
     */
    public static void append(Path file, ChatMessage msg) throws IOException {
        // 确保目录存在
        Files.createDirectories(file.getParent());

        // 序列化成一行 JSON（不格式化）
        String line = MAPPER.writeValueAsString(msg) + "\n";

        // ★ 追加写，不重写整个文件
        Files.writeString(file, line, 
            StandardOpenOption.CREATE,      // 不存在就创建
            StandardOpenOption.APPEND);     // 追加模式
    }

    /**
     * 批量追加（一次性写多条，减少 IO）
     */
    public static void appendAll(Path file, List<ChatMessage> msgs) throws IOException {
        Files.createDirectories(file.getParent());
        StringBuilder sb = new StringBuilder();
        for (ChatMessage msg : msgs) {
            sb.append(MAPPER.writeValueAsString(msg)).append("\n");
        }
        Files.writeString(file, sb.toString(),
            StandardOpenOption.CREATE,
            StandardOpenOption.APPEND);
    }
}
```

### 逐段详解

#### 1. 为什么禁用 pretty print？

```
private static final ObjectMapper MAPPER = new ObjectMapper()
    .disable(SerializationFeature.INDENT_OUTPUT);
```

**JSONL 要求一行一个 JSON 对象。**

如果启用了 pretty print，一个对象会变成多行：

```
{
  "role": "user",
  "content": "你好"
}
```

这就不是 JSONL 了，读取的时候会把每一行当成一个独立的 JSON，解析失败。

**所以必须禁用格式化，保证一行一个完整的 JSON。**

#### 2. 追加写

```
Files.writeString(file, line, 
    StandardOpenOption.CREATE,
    StandardOpenOption.APPEND);
```

**两个选项：**

- `CREATE`：文件不存在就创建
- `APPEND`：追加模式，不覆盖原有内容

**对比旧方式：**

```
// 旧：覆盖写，每次重写整个文件
Files.writeString(file, json);

// 新：追加写，只写新的一行
Files.writeString(file, line, CREATE, APPEND);
```

**追加写的好处：**

- O (1) 时间，不管历史多长
- 崩溃只丢最后一行（最多这一行不完整）
- 前面的内容永远安全

#### 3. 批量追加

```
public static void appendAll(Path file, List<ChatMessage> msgs) {
    StringBuilder sb = new StringBuilder();
    for (ChatMessage msg : msgs) {
        sb.append(MAPPER.writeValueAsString(msg)).append("\n");
    }
    Files.writeString(file, sb.toString(), CREATE, APPEND);
}
```

**一次性写多条，减少 IO 次数。**

比如初始化会话时，可能要一次性写 system prompt 和几条历史消息，用 appendAll 比循环 append 快。

## 第二步：恢复 + 容错

```
// memory/SessionArchiver.java（续）

    /**
     * 加载 JSONL 文件，容错恢复
     * 坏行跳过，不崩溃
     */
    public static List<ChatMessage> load(Path file) throws IOException {
        if (!Files.exists(file)) {
            return new ArrayList<>();
        }

        List<ChatMessage> msgs = new ArrayList<>();

        try (BufferedReader reader = Files.newBufferedReader(file)) {
            String line;
            int lineNum = 0;

            while ((line = reader.readLine()) != null) {
                lineNum++;

                // 跳过空行
                if (line.isBlank()) {
                    continue;
                }

                try {
                    ChatMessage msg = MAPPER.readValue(line, ChatMessage.class);
                    msgs.add(msg);
                } catch (Exception e) {
                    // ★ 坏行跳过，不崩溃
                    System.err.println("[Session] 跳过坏行: " 
                        + file.getFileName() + ":" + lineNum 
                        + " - " + e.getMessage());
                }
            }
        }

        // ★ 截断：最后一条是 assistant+tool_use 但没有配对的 tool_result
        msgs = truncateIncompleteToolUse(msgs);

        return msgs;
    }

    /**
     * 截断不完整的 tool_use
     * 如果最后一条是 assistant 消息且包含 tool_use，但后面没有 tool_result，
     * 说明程序在工具执行前崩溃了，这条消息不完整，移除它。
     */
    private static List<ChatMessage> truncateIncompleteToolUse(List<ChatMessage> msgs) {
        if (msgs.isEmpty()) {
            return msgs;
        }

        ChatMessage last = msgs.get(msgs.size() - 1);

        // 最后一条是 assistant，且有 tool_use
        if ("assistant".equals(last.role()) && last.toolCalls() != null 
                && !last.toolCalls().isEmpty()) {
            // 检查后面有没有 tool_result（实际上它就是最后一条，所以没有）
            // 移除这条不完整的消息
            System.out.println("[Session] 截断不完整的 tool_use 消息");
            msgs.remove(msgs.size() - 1);
        }

        return msgs;
    }
```

### 逐段详解

#### 1. 逐行读取

```
try (BufferedReader reader = Files.newBufferedReader(file)) {
    String line;
    while ((line = reader.readLine()) != null) {
        // 处理每一行
    }
}
```

**流式读取，不用一次性加载整个文件。**

try-with-resources 保证 reader 自动关闭。

#### 2. 跳过空行

```
if (line.isBlank()) {
    continue;
}
```

文件里可能有空行（比如手动编辑过，或者写入时多了换行），跳过。

#### 3. 坏行跳过

```
try {
    ChatMessage msg = MAPPER.readValue(line, ChatMessage.class);
    msgs.add(msg);
} catch (Exception e) {
    System.err.println("[Session] 跳过坏行: " + ...);
}
```

**★ 这是容错的关键。**

某一行 JSON 损坏了（比如崩溃导致最后一行不完整），不应该让整个恢复失败。

- 解析成功 → 加入列表
- 解析失败 → 打印警告，跳过这一行，继续

**对比旧方式：**

```
// 旧：整个文件反序列化，一条坏数据 → 全丢
List<ChatMessage> msgs = MAPPER.readValue(file, new TypeReference<>() {});
```

旧方式只要有一条坏数据，整个文件解析失败，全部历史都没了。

#### 4. 截断不完整的 tool_use

```
private static List<ChatMessage> truncateIncompleteToolUse(List<ChatMessage> msgs) {
    ChatMessage last = msgs.get(msgs.size() - 1);

    if ("assistant".equals(last.role()) && last.toolCalls() != null 
            && !last.toolCalls().isEmpty()) {
        // 最后一条是 assistant+tool_use，但没有后续的 tool_result
        // 说明程序在工具执行前崩溃了
        msgs.remove(msgs.size() - 1);
    }

    return msgs;
}
```

**为什么要截断？**

Agent Loop 的流程是：

```
1. LLM 返回 assistant 消息（包含 tool_use）
2. 保存这条 assistant 消息
3. 执行工具
4. 保存 tool_result 消息
```

如果在第 2 步之后、第 4 步之前崩溃了：

- 存档里有 assistant+tool_use
- 但没有对应的 tool_result
- 恢复后，LLM 看到 tool_use 但没有结果，会困惑

**所以恢复时要截断这条不完整的消息，让 LLM 重新生成。**

## 第三步：时间跨度提醒

恢复会话时，如果两条消息间隔超过 1 小时，插入一条提示，让 AI 知道上下文可能不连续。

```
// memory/SessionArchiver.java（续）

    /**
     * 加载并插入时间跨度提醒
     * 在间隔 > 1 小时的消息之间插入提示
     */
    public static List<ChatMessage> loadWithTimeMarkers(Path file) throws IOException {
        List<ChatMessage> msgs = load(file);

        if (msgs.size() < 2) {
            return msgs;
        }

        List<ChatMessage> result = new ArrayList<>();
        result.add(msgs.get(0));

        for (int i = 1; i < msgs.size(); i++) {
            ChatMessage prev = msgs.get(i - 1);
            ChatMessage curr = msgs.get(i);

            // 计算时间差
            long gapMinutes = calculateGapMinutes(prev, curr);

            if (gapMinutes >= 60) {
                // 插入时间跨度提醒
                String marker = formatTimeMarker(gapMinutes);
                result.add(new ChatMessage("user", marker));
            }

            result.add(curr);
        }

        return result;
    }

    /**
     * 计算两条消息的时间差（分钟）
     */
    private static long calculateGapMinutes(ChatMessage a, ChatMessage b) {
        // ChatMessage 需要有 timestamp 字段
        // 如果没有，返回 0
        if (a.timestamp() == null || b.timestamp() == null) {
            return 0;
        }
        Instant t1 = a.timestamp();
        Instant t2 = b.timestamp();
        return java.time.Duration.between(t1, t2).toMinutes();
    }

    /**
     * 格式化时间跨度提示
     */
    private static String formatTimeMarker(long minutes) {
        if (minutes < 60) {
            return "[ " + minutes + " 分钟前的对话 ]";
        }
        long hours = minutes / 60;
        long remainMinutes = minutes % 60;
        if (hours < 24) {
            return "[ " + hours + " 小时 " + remainMinutes + " 分钟前的对话，"
                + "上下文可能不连续，请确认当前需求 ]";
        }
        long days = hours / 24;
        return "[ " + days + " 天前的对话，上下文可能已过时，"
            + "请重新确认用户需求 ]";
    }
```

### 为什么需要时间跨度提醒？

**场景：**

- 周一聊了一半，用户有事走了
- 周五回来继续聊
- AI 以为是连续的对话，但其实过了 4 天
- 项目可能已经变了，用户的需求可能也变了

**插入提醒后：**

```
[user] 帮我重构一下这个类
[assistant] 好的，我先看看...
[user] [ 4 天前的对话，上下文可能已过时，请重新确认用户需求 ]
[user] 继续
```

AI 看到提醒，就会知道这是隔了很久的对话，可能需要重新确认需求，而不是直接继续。

**时间跨度分级：**

- 1-24 小时："X 小时前的对话"
- 24 小时以上："X 天前的对话，上下文可能已过时"

## 第四步：30 天自动清理

```
// memory/SessionArchiver.java（续）

    /**
     * 清理 N 天前的旧会话文件
     * @return 清理的文件数
     */
    public static int cleanOld(Path dir, int days) throws IOException {
        if (!Files.exists(dir)) {
            return 0;
        }

        Instant cutoff = Instant.now().minus(days, java.time.temporal.ChronoUnit.DAYS);
        int cleaned = 0;

        try (DirectoryStream<Path> stream = Files.newDirectoryStream(dir, "*.jsonl")) {
            for (Path file : stream) {
                try {
                    Instant lastModified = Files.getLastModifiedTime(file).toInstant();
                    if (lastModified.isBefore(cutoff)) {
                        Files.delete(file);
                        cleaned++;
                        System.out.println("[Session] 清理旧会话: " 
                            + file.getFileName());
                    }
                } catch (Exception e) {
                    System.err.println("[Session] 清理失败: " 
                        + file.getFileName() + " - " + e.getMessage());
                }
            }
        }

        return cleaned;
    }

    /**
     * 默认清理 30 天前的会话
     */
    public static int cleanOld(Path dir) throws IOException {
        return cleanOld(dir, 30);
    }
```

### 逐段详解

#### 1. 计算截止时间

```
Instant cutoff = Instant.now().minus(days, ChronoUnit.DAYS);
```

比如今天是 8 月 13 日，days=30，cutoff 就是 7 月 14 日。

7 月 14 日之前修改的文件都要删。

#### 2. 遍历文件

```
try (DirectoryStream<Path> stream = Files.newDirectoryStream(dir, "*.jsonl")) {
    for (Path file : stream) {
        // 检查每个 .jsonl 文件
    }
}
```

只处理 `.jsonl` 文件，不碰其他文件。

#### 3. 检查修改时间

```
Instant lastModified = Files.getLastModifiedTime(file).toInstant();
if (lastModified.isBefore(cutoff)) {
    Files.delete(file);
    cleaned++;
}
```

文件最后修改时间在截止时间之前 → 删除。

**为什么用修改时间不用创建时间？**

- 创建时间在不同文件系统上不一定可靠
- 修改时间更准确：最后一次活跃的时间
- 会话可能创建了但一直没用，修改时间还是创建时的时间

#### 4. 单个文件失败不影响其他

```
try {
    // 删除
} catch (Exception e) {
    System.err.println("清理失败: " + ...);
}
```

某个文件删不掉（比如权限不够），不影响其他文件的清理。

## 第五步：Session 集成

把存档功能集成到 Session 类里。

```
// session/Session.java
package com.rook.session;

import com.rook.llm.ChatMessage;
import com.rook.memory.SessionArchiver;
import java.io.IOException;
import java.nio.file.*;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;
import java.util.*;

public class Session {

    private final Path archiveFile;
    private final List<ChatMessage> history;

    public Session(Path sessionsDir) throws IOException {
        // 生成会话文件名：时间戳 + 随机数
        String timestamp = LocalDateTime.now()
            .format(DateTimeFormatter.ofPattern("yyyyMMdd-HHmmss"));
        String random = String.format("%04d", (int)(Math.random() * 10000));
        String fileName = timestamp + "-" + random + ".jsonl";
        this.archiveFile = sessionsDir.resolve(fileName);

        this.history = new ArrayList<>();

        // 启动时清理旧会话
        SessionArchiver.cleanOld(sessionsDir);
    }

    /**
     * 恢复已有会话
     */
    public static Session resume(Path archiveFile) throws IOException {
        Session session = new Session(archiveFile.getParent());
        // 加载历史，带时间跨度提醒
        List<ChatMessage> loaded = SessionArchiver.loadWithTimeMarkers(archiveFile);
        session.history.addAll(loaded);
        return session;
    }

    /**
     * 添加消息并存档
     */
    public void addMessage(ChatMessage msg) throws IOException {
        history.add(msg);
        // ★ 每条消息都追加存档
        SessionArchiver.append(archiveFile, msg);
    }

    /**
     * 获取历史
     */
    public List<ChatMessage> getHistory() {
        return Collections.unmodifiableList(history);
    }

    /**
     * 获取存档文件路径
     */
    public Path getArchiveFile() {
        return archiveFile;
    }

    /**
     * 列出所有会话
     */
    public static List<Path> listSessions(Path sessionsDir) throws IOException {
        if (!Files.exists(sessionsDir)) {
            return List.of();
        }
        List<Path> files = new ArrayList<>();
        try (DirectoryStream<Path> stream = 
                Files.newDirectoryStream(sessionsDir, "*.jsonl")) {
            for (Path f : stream) {
                files.add(f);
            }
        }
        // 按修改时间倒序（最新的在前）
        files.sort((a, b) -> {
            try {
                return Files.getLastModifiedTime(b)
                    .compareTo(Files.getLastModifiedTime(a));
            } catch (IOException e) {
                return 0;
            }
        });
        return files;
    }
}
```

### 逐段详解

#### 1. 生成文件名

```
String timestamp = LocalDateTime.now()
    .format(DateTimeFormatter.ofPattern("yyyyMMdd-HHmmss"));
String random = String.format("%04d", (int)(Math.random() * 10000));
String fileName = timestamp + "-" + random + ".jsonl";
```

文件名格式：`20260813-153045-1234.jsonl`

- 时间戳：方便知道是什么时候的会话
- 随机数：防止同一秒创建多个会话重名

#### 2. 启动时清理旧会话

```
SessionArchiver.cleanOld(sessionsDir);
```

每次创建新会话时，清理一下 30 天前的旧会话。

不用单独的定时任务，简单有效。

#### 3. 每条消息都存档

```
public void addMessage(ChatMessage msg) throws IOException {
    history.add(msg);
    SessionArchiver.append(archiveFile, msg);  // 追加写
}
```

**每条消息添加到内存的同时，追加写到文件。**

这样即使崩溃，内存里的历史丢了，文件里还有。

#### 4. 恢复会话

```
public static Session resume(Path archiveFile) throws IOException {
    Session session = new Session(archiveFile.getParent());
    List<ChatMessage> loaded = SessionArchiver.loadWithTimeMarkers(archiveFile);
    session.history.addAll(loaded);
    return session;
}
```

从文件加载历史，带时间跨度提醒。

#### 5. 列出所有会话

```
public static List<Path> listSessions(Path sessionsDir) {
    // 列出所有 .jsonl 文件
    // 按修改时间倒序（最新的在前）
}
```

用于 `:sessions` 命令，显示所有历史会话，让用户选择恢复哪个。

## 常见坑（详细版）

### 1. JSONL 不能格式化

**现象：** 保存的 JSONL 文件，读取时全是坏行。

**原因：** 启用了 Jackson 的 pretty print，一个 JSON 对象变成了多行。

**错误：**

```
ObjectMapper mapper = new ObjectMapper()
    .enable(SerializationFeature.INDENT_OUTPUT);  // ❌ 不能启用
```

**正确：**

```
ObjectMapper mapper = new ObjectMapper()
    .disable(SerializationFeature.INDENT_OUTPUT);  // ✅ 必须禁用
```

**JSONL 的铁律：一行一个完整的 JSON，不能有换行。**

### 2. tool_use /tool_result 配对

**现象：** 恢复后，AI 行为异常，或者报错 "找不到工具结果"。

**原因：** 崩溃时，assistant 的 tool_use 消息保存了，但 tool_result 还没保存。

恢复后，历史里有 tool_use 但没有对应的结果。

**解决：**

- 恢复时检查最后一条消息
- 如果是 assistant+tool_use，且没有后续的 tool_result → 截断它
- 让 LLM 重新生成

**更彻底的方案：**

- 把 assistant+tool_use 和 tool_result 当成一个原子单元
- 要么都保存，要么都不保存
- 但实现复杂，截断是简单有效的方案

### 3. 旧格式兼容

**现象：** 升级后，老版本保存的 JSON 数组格式文件读不了。

**原因：** 老版本用的是整个 JSON 数组，新版本用 JSONL，格式不一样。

**解决：**

- 检测文件格式：第一行是 `[` → 旧格式（JSON 数组）
- 旧格式一次性转换：读出来，转成 JSONL 写回去
- 或者提供迁移工具，一次性转换所有旧文件

**迁移代码示例：**

```
// 检测是不是旧格式
String firstLine = Files.readAllLines(file).get(0);
if (firstLine.trim().startsWith("[")) {
    // 旧格式：JSON 数组
    List<ChatMessage> msgs = MAPPER.readValue(file, new TypeReference<>() {});
    // 转成 JSONL
    Files.delete(file);
    SessionArchiver.appendAll(file, msgs);
}
```

### 4. 并发写入

**现象：** 多线程同时写，文件内容混乱。

**原因：** JSONL 追加写不是原子操作，多个线程同时写可能交错。

**解决：**

- Session 的 addMessage 加 synchronized
- 或者用单线程写队列
- 我们的 Agent Loop 是单线程的，所以没问题

### 5. 大文件加载慢

**现象：** 恢复一个很长的会话（几千条消息），等很久。

**原因：** 逐行读取 + 逐条反序列化，消息多了就慢。

**优化：**

- 只加载最近 N 条消息（比如最近 100 条）
- 或者分页加载
- 或者用第 15 章的上下文压缩，先压缩再加载

### 6. 时间戳字段缺失

**现象：** 时间跨度提醒不生效。

**原因：** ChatMessage 没有 timestamp 字段，或者老消息没有时间戳。

**解决：**

- ChatMessage 加 timestamp 字段，默认值为当前时间
- 老消息没有时间戳的，calculateGapMinutes 返回 0，不插入提醒
- 不影响正常功能

### 7. 文件编码问题

**现象：** 中文消息保存后乱码。

**原因：** Windows 默认编码是 GBK，Files.writeString 可能用系统默认编码。

**解决：**

- 显式指定 UTF-8：

```
Files.writeString(file, line, StandardCharsets.UTF_8, CREATE, APPEND);
```

- 读取时也指定 UTF-8：

```
Files.newBufferedReader(file, StandardCharsets.UTF_8)
```

### 8. 清理时文件被占用

**现象：** Windows 上清理旧会话失败，报 "文件被占用"。

**原因：** 某个会话还在使用中，文件被锁定。

**解决：**

- 清理时跳过当前正在使用的会话文件
- 或者捕获异常，打印警告，继续清理其他文件
- 我们的实现里单个文件失败不影响其他，已经处理了

## JSONL vs JSON 数组对比

|    维度    | JSON 数组（旧）  |    JSONL（新）     |
| :--------: | :--------------: | :----------------: |
|  写入方式  |   整个文件重写   |      追加一行      |
| 写入复杂度 |       O(n)       |        O(1)        |
|  崩溃损失  |     全部丢失     |    最多最后一行    |
| 坏数据影响 |   全部解析失败   | 跳过坏行，其他正常 |
|  读取方式  |    一次性加载    |      逐行流式      |
|  内存占用  |  大（整个文件）  |     小（逐行）     |
|    格式    | 可格式化（缩进） |    必须一行一个    |

**JSONL 是日志类数据的标准格式，适合追加写的场景。**
