# 04 — JLine3 终端交互界面

## 这一章做什么

用 JLine3 搭一个带命令补全、历史记录和多行粘贴检测的 **REPL 交互循环**。

**完成后你能做到：**

- 程序启动后持续运行，用户可以一直输入
- 按 ↑ ↓ 回溯历史输入
- 按 Tab 自动补全命令
- 粘贴多行代码时自动识别，不会每行都发一次
- `/` 开头的是命令，普通文本是对话

## 为什么需要

没有 REPL，程序启动一次就退出，每次问问题都要重新跑程序，体验很差。

**REPL 是什么？**

- **R**ead — 读取用户输入
- **E**val — 执行（送 AI 或执行命令）
- **P**rint — 打印结果
- **L**oop — 循环回去等下一个输入

就是你平时用的命令行终端那种感觉：输入一行，执行一行，不断循环。

## 核心概念

### JLine3

一个 Java 的终端操作库，让你能做出像 bash、zsh 那样的高级命令行体验。

**为什么不用 Scanner？**

- Scanner 只能读一行纯文本
- 没有历史记录
- 没有命令补全
- 没有颜色、光标移动等高级功能
- 跨平台问题多（Windows 上各种坑）

**JLine3 提供什么：**

- **Terminal** — 抽象的终端对象，跨平台兼容
- **LineReader** — 行编辑器，支持历史、补全、快捷键
- **History** — 历史记录管理
- **Completer** — 自动补全
- **Color** — 终端颜色输出

### 输入分流

判断用户输入的是命令还是对话：

- `/` 开头 → 命令（`/help`、`/exit`、`/model` 等），本地处理
- 普通文本 → 送给 AI 对话

**为什么要分流？**

- 命令需要即时响应，不用调 API
- 有些操作是控制程序本身的，不是跟 AI 聊天
- 比如切换模型、查看历史、清空会话这些

### 多行粘贴

检测用户是不是在粘贴多行内容（比如一段代码），如果是，等用户粘贴完（空行结束）再一起发给 AI。

**为什么需要？**

如果没有多行检测，用户粘贴一段代码：

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("hello");
    }
}
```

程序会每行都发一次给 AI，发 5 次，得到 5 个回答，完全乱了。

**多行检测的思路：**

- 看行尾是不是 `{`、`(`、`,` 这种 "未完成" 符号 → 继续等
- 看行首是不是缩进 → 代码续行，继续等
- 遇到空行 → 结束，一起发送

## 第一步：最小 REPL

先从最简单的版本开始，理解核心流程。

```java
// cli/Repl.java (最小版)
public class Repl {
    public void start() {
        // 1. 创建终端
        Terminal terminal = TerminalBuilder.builder().build();
        
        // 2. 创建行读取器
        LineReader reader = LineReaderBuilder.builder()
            .terminal(terminal)
            .build();

        // 3. 打印欢迎信息
        System.out.println("Rook > ");
        
        // 4. 主循环
        while (true) {
            // 读取一行输入
            String input = reader.readLine("> ");
            
            // 空行跳过
            if (input == null || input.isBlank()) continue;
            
            // 输入 :exit 就退出
            if (":exit".equals(input.trim())) break;
            
            // 回显（实际项目里是送 AI）
            System.out.println("你说: " + input);
        }
    }
}
```

### 逐行解释

#### 1. 创建 Terminal

```
Terminal terminal = TerminalBuilder.builder().build();
```

**Terminal 是什么？**

抽象的终端对象，封装了底层的终端操作。

**自动检测：**

- Windows 上用 Jansi 或 JNA 模拟终端
- macOS/Linux 上用系统终端
- 非交互环境（管道、重定向）自动降级为 dumb terminal

**为什么需要 Terminal？**

直接用 System.out 也能打印，但 Terminal 提供了：

- 获取终端大小（行列数）
- 光标移动
- 颜色支持
- 信号处理（Ctrl+C）
- 跨平台兼容

#### 2. 创建 LineReader

```java
LineReader reader = LineReaderBuilder.builder()
    .terminal(terminal)
    .build();
```

**LineReader 是什么？**

行编辑器，就是负责 "读一行输入" 的核心组件。

**它提供的能力：**

- 历史记录（↑ ↓ 翻历史）
- 行内编辑（← → 移动光标，退格删除）
- 快捷键（Ctrl+A 行首、Ctrl+E 行尾、Ctrl+U 删除整行等）
- 自动补全（Tab）
- 多行编辑

**和 BufferedReader.readLine () 的区别：**

- BufferedReader 只能读字符，没有编辑功能
- LineReader 是完整的行编辑器，体验像 bash

#### 3. 主循环

```
while (true) {
    String input = reader.readLine("> ");
    if (input == null || input.isBlank()) continue;
    if (":exit".equals(input.trim())) break;
    System.out.println("你说: " + input);
}
```

**`reader.readLine("> ")` 做了什么？**

- 打印提示符 `> `
- 等待用户输入
- 用户可以用各种快捷键编辑这一行
- 用户按回车后，返回输入的字符串

**`input == null` 是什么情况？**

- 用户按了 Ctrl+D（EOF）
- 输入流结束了
- 这种情况应该退出循环

**`input.isBlank()` 判断什么？**

- 空字符串或全是空格
- 这种情况跳过，不处理

## 第二步：加分流和多行检测

实际项目里，REPL 要处理两种输入：命令和对话。还要支持多行粘贴。

```java
// 去掉尾部空白
input = input.stripTrailing();

// ★ 多行检测
if (looksIncomplete(input)) {
    StringBuilder sb = new StringBuilder(input);
    while (true) {
        String next = reader.readLine("  ");  // 续行提示符是两个空格
        if (next == null) break;
        next = next.stripTrailing();
        if (next.isEmpty()) break;           // 空行 = 结束
        sb.append("\n").append(next);
        if (!looksIncomplete(next)) break;   // 这行看起来"完整"了，也结束
    }
    input = sb.toString().trim();
}

// ★ 分流
if (input.startsWith("/")) {
    // 命令：交给命令分发器
    String feedText = dispatcher.dispatch(input, this);
    if (feedText != null) processMessage(feedText); // 命令结果可以喂回对话
} else {
    // 普通文本：送 AI 对话
    processMessage(input);
}
```

### 多行检测详解

#### 为什么需要多行？

**场景 1：粘贴代码**

用户粘贴一段 Java 代码，5 行，我们要等用户粘贴完，把 5 行一起发给 AI。

**场景 2：手动输入多行**

用户想输入一段长文本，每行按回车继续，最后用空行结束。

#### 多行检测的逻辑

```
第一行输入 → 判断是不是"未完成"的
  ├─ 是 → 继续读下一行
  └─ 否 → 直接发送

继续读下一行 → 判断
  ├─ 空行 → 结束，一起发送
  ├─ 还是未完成 → 继续读
  └─ 看起来完成了 → 结束，一起发送
```

#### 续行提示符

```
String next = reader.readLine("  ");
```

续行的提示符是两个空格，不是 `> `，这样用户能看出来现在是多行模式。

```
> public class Main {    ← 第一行，提示符 >
  public static void     ← 第二行，提示符是两个空格，表示续行
```

#### 什么时候结束多行？

两种情况：

1. **遇到空行** — 用户按了两次回车，表示输入完了
2. **当前行看起来 "完整" 了** — 比如以 `}`、`;` 结尾，可能是最后一行

**为什么两种都要？**

- 只靠空行：用户可能忘了空行，一直等
- 只靠行尾判断：有些代码格式不标准，会误判
- 两个都有：更鲁棒

### 输入分流详解

#### 命令模式

```
if (input.startsWith("/")) {
    String feedText = dispatcher.dispatch(input, this);
    if (feedText != null) processMessage(feedText);
}
```

**`/` 开头的是命令**，比如：

- `/help` — 显示帮助
- `/exit` — 退出程序
- `/model` — 切换模型
- `/clear` — 清空对话
- `/history` — 查看历史

**命令的特点：**

- 本地执行，不用调 API
- 响应快
- 用来控制程序本身

**`dispatcher.dispatch()` 是什么？**

命令分发器，根据命令名调用对应的处理函数。

**`feedText` 是什么？**

有些命令执行完后，可以返回一段文本，喂回对话流程。

比如 `/prompt xxx` 命令设置了一个 prompt，可以把这个 prompt 当作用户输入发给 AI。

#### 对话模式

```
} else {
    processMessage(input);
}
```

**普通文本送 AI**，走对话流程。

**为什么要分流？**

- 命令是控制程序的，不用 AI 参与
- 对话是跟 AI 聊天的，要调 API
- 分开处理，逻辑清晰

## 第三步：多行判断逻辑

这是多行检测的核心，判断一行是不是 "未完成" 的。

```
private static boolean looksIncomplete(String line) {
    if (line == null || line.isEmpty()) return false;
    String s = line.stripTrailing();
    
    // { ( , 结尾 → 未完成
    if (s.endsWith("{") || s.endsWith("(") || s.endsWith(",")) return true;
    
    // ; } 结尾 → 完成
    if (s.endsWith(";") || s.endsWith("}")) return false;
    
    // 缩进开头 → 续行（代码里的缩进）
    if (!s.isEmpty() && Character.isWhitespace(line.charAt(0))) return true;
    
    return false;
}
```

### 逐条规则解释

#### 规则 1：行尾是 `{`、`(`、`,` → 未完成

```
if (s.endsWith("{") || s.endsWith("(") || s.endsWith(",")) return true;
```

**例子：**

- `public class Main {` → `{` 结尾，后面肯定还有内容
- `if (a > 0 &&` → 不对，这个是 `&&` 结尾，不在列表里
- `List<String> list = List.of(` → `(` 结尾，参数列表还没写完
- `int a = 1,` → `,` 结尾，后面应该还有

**为什么这些符号表示未完成？**

这些都是 "开口" 的符号，后面肯定要跟上内容：

- `{` 开启代码块
- `(` 开启参数列表
- `,` 表示列表还有下一项

#### 规则 2：行尾是 `;`、`}` → 完成

```
if (s.endsWith(";") || s.endsWith("}")) return false;
```

**例子：**

- `System.out.println("hello");` → `;` 结尾，语句结束
- `}` → 代码块结束

**为什么先判断 "未完成" 再判断 "完成"？**

因为优先级不同。如果一行同时满足两个条件（虽然不太可能），先算未完成的。

#### 规则 3：行首是缩进 → 续行

```
if (!s.isEmpty() && Character.isWhitespace(line.charAt(0))) return true;
```

**例子：**

```
public class Main {      ← 第一行，{ 结尾 → 未完成
    public static void   ← 第二行，开头有空格（缩进） → 未完成
```

**为什么缩进表示续行？**

代码都是缩进的，比如方法体里的代码比方法声明多一层缩进。如果一行以空格或 tab 开头，很可能是代码的续行。

**注意：用的是原始的 `line`，不是 `stripTrailing()` 后的 `s`**

因为我们要判断行首是不是空白，stripTrailing () 只去尾部空白，不影响行首。

### 这个判断准确吗？

**不是 100% 准确，是启发式的。**

**可能误判的情况：**

- 普通文本以 `{` 结尾（比如用户写 "我有一个 {问题"）→ 会误判为多行
- 代码没有缩进 → 可能识别不出来

**但够用了：**

- 大部分代码场景都能正确识别
- 就算误判了，用户按个空行就能发送，影响不大
- 比完全没有多行支持好太多

## 第四步：processMessage — 调 LLM

用户输入的普通文本，送到这里处理：调 LLM，流式打印回复。

```java
private void processMessage(String input) {
    // 1. 把用户消息加入会话历史
    session.addMessage(new ChatMessage("user", input));
    
    try {
        StringBuilder fullReply = new StringBuilder();
        
        // 2. 调用 LLM 流式接口
        currentProvider.stream(session.getMessages(), token -> {
            System.out.print(token);        // ★ 逐字实时打印
            System.out.flush();             // 强制刷新，确保立刻显示
            fullReply.append(token);        // 同时攒起来，最后存历史
        });
        
        System.out.println();  // 回复结束，换行
        
        // 3. 把 AI 回复加入会话历史
        session.addMessage(new ChatMessage("assistant", fullReply.toString()));
        
    } catch (LlmException e) {
        System.err.println("错误: " + e.getMessage());
    }
}
```

### 逐段解释

#### 1. 加入用户消息

```
session.addMessage(new ChatMessage("user", input));
```

把用户输入存到会话历史里。

**为什么要存历史？**

大模型是无状态的，每次请求都要把完整的对话历史发过去，它才能理解上下文。

```
第 1 轮：
  messages = [用户：你好]
  AI 回复：你好！

第 2 轮：
  messages = [用户：你好, AI：你好！, 用户：今天天气怎么样]  ← 要把历史都带上
  AI 回复：今天天气很好
```

如果不带历史，AI 就不知道之前聊了什么。

#### 2. 流式调用 + 逐字打印

```
currentProvider.stream(session.getMessages(), token -> {
    System.out.print(token);        // 逐字打印
    System.out.flush();             // 强制刷新
    fullReply.append(token);        // 攒起来
});
```

**三个动作：**

1. **打印 token** — 用户能看到打字效果
2. **刷新缓冲区** — 确保立刻显示，不会攒到缓冲区满了才出来
3. **追加到 StringBuilder** — 把完整回复攒起来，最后存历史

**为什么要 `System.out.flush()`？**

PrintStream 默认是缓冲的，攒到一定量才输出。如果不 flush，可能会看到 "卡一下，然后出来一堆字" 的效果，不是流畅的打字机。

**为什么要同时存到 fullReply？**

流式回调是一个 token 一个 token 来的，我们需要把它们拼起来，最后作为完整的 AI 回复存到历史里。

#### 3. 加入 AI 回复

```
session.addMessage(new ChatMessage("assistant", fullReply.toString()));
```

把 AI 的完整回复也存到历史里，下一轮对话时一起发过去。

#### 4. 异常处理

```
} catch (LlmException e) {
    System.err.println("错误: " + e.getMessage());
}
```

API 调用失败时，打印错误信息，程序继续运行，不会崩溃。

## 常见坑（详细版）

### 1. JLine 找不到终端

**现象：** 启动时报错，或者终端功能受限（没有颜色、没有历史）。

**原因：** 在非交互环境下运行，比如：

- 管道输入：`echo "hello" | java -jar app.jar`
- 输出重定向：`java -jar app.jar > output.txt`
- IDE 里运行（有些 IDE 的控制台不是完整终端）

**JLine 的处理：**

自动降级为 **dumb terminal**（哑终端），基本功能还能用，但高级功能（颜色、光标移动）会失效。

**这是正常的，不是 bug。** 程序不会崩，只是体验差一点。

### 2. 中文输入乱码

**现象：** 输入中文显示成问号或乱码。

**原因：** 编码不一致。

- Windows 控制台默认 GBK
- JLine 默认 UTF-8
- 两边对不上就乱码

**解决方法：**

1. 确保 JVM 启动参数加了 `-Dfile.encoding=UTF-8`
2. Windows 上可以用 `chcp 65001` 切换控制台编码
3. JLine 3 的新版本对中文支持已经很好了，一般不会有问题

### 3. Ctrl+C 崩溃

**现象：** 用户按 Ctrl+C，程序直接崩了，或者抛异常。

**原因：** Ctrl+C 会发送中断信号，默认行为是终止程序。

**正确处理：**

- **空闲状态**（等用户输入时）按 Ctrl+C → 应该退出程序（或者问 "确定要退出吗？"）
- **流式输出时**按 Ctrl+C → 应该停止当前输出，回到输入状态，不是退出整个程序

**JLine 的处理：**

会抛出 `UserInterruptException`，你可以捕获它，根据状态做不同处理。

```
try {
    String input = reader.readLine("> ");
} catch (UserInterruptException e) {
    // Ctrl+C 了
    if (正在流式输出) {
        停止流式输出;
    } else {
        退出程序;
    }
}
```

### 4. 历史记录不保存

**现象：** 退出后再进来，历史记录没了。

**原因：** 默认情况下，历史只存在内存里，退出就没了。

**解决：** 配置 History，指定保存到文件：

```
History history = new DefaultHistory();
((DefaultHistory) history).setPath(Paths.get("~/.rook/history"));
LineReader reader = LineReaderBuilder.builder()
    .terminal(terminal)
    .history(history)
    .build();
```

这样历史就持久化了，下次启动还能看到之前的输入。

### 5. 粘贴大段文本时卡顿

**现象：** 粘贴一大段文本，终端卡住。

**原因：** JLine 的 bracketed paste mode（括号粘贴模式）没开，粘贴的文本被当成一个个按键处理。

**解决：** 开启 bracketed paste mode，粘贴时一次性处理。JLine 3 默认是支持的，一般不用手动配置。
