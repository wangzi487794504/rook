# 19 — 斜杠命令系统

## 这一章做什么

用 **CommandRegistry** 统一管理 12 个内置命令，支持三种执行类型（本地 / 界面 / 提示词注入），以及 Tab 补全菜单。

**完成后你能做到：**

- 加一个新命令？写一个类，`registry.register()` 一行搞定
- 不用改 Repl、不用改 help、不用改补全，自动全部生效
- 命令可以纯输出、可以改界面、可以注入消息触发 AI
- 输入 `/` 按 Tab，弹出所有命令的补全菜单

## 为什么需要

### 旧方式的问题

之前命令散落在 Repl 的 switch-case 里：

```
// 旧方式
if (input.startsWith("/")) {
    String cmd = input.split(" ")[0];
    switch (cmd) {
        case "/help" -> printHelp();
        case "/exit" -> exit();
        case "/clear" -> clearScreen();
        case "/plan" -> setPlanMode();
        // ... 更多命令
        default -> System.out.println("未知命令");
    }
}
```

**问题：**

|      问题      |                说明                 |
| :------------: | :---------------------------------: |
| 加命令要改多处 | 改 switch、改 help 文本、改补全逻辑 |
|  没有统一结构  | 每个命令的参数、描述、用法都不统一  |
|   别名难管理   |    想给命令加别名？又要改 switch    |
|   补全难实现   |       要单独维护一份命令列表        |
|    代码膨胀    |       命令多了，switch 几百行       |

### 注册中心的优势

```
// 新方式
registry.register(new Command(
    "/help", List.of("/?"), "显示帮助", ..., handler
));
```

**加一个命令只需要：**

1. 写一个 Command 对象
2. register 一下

**自动生效：**

- 自动出现在 /help 里
- 自动支持别名
- 自动支持 Tab 补全
- 自动有统一的错误处理

## 核心概念

### CommandRegistry

- 用 `Map<String, Command>` 存储所有命令
- 启动时检测别名冲突，有冲突直接 panic（不让运行时才发现）
- 提供查找、补全、列出等方法

### 三种命令类型

|       类型       |          含义          |            示例            |       返回值        |
| :--------------: | :--------------------: | :------------------------: | :-----------------: |
|    **LOCAL**     | 纯本地输出，不影响对话 |     `/help`、`/status`     |   null（只打印）    |
| **UI_AFFECTING** |     改变界面或状态     | `/exit`、`/clear`、`/plan` |        null         |
| **PROMPT_FEED**  |    注入消息触发 LLM    |      `/do`、`/review`      | 非 null（注入文本） |

### Console 接口

命令不直接绑定 JLine 或 System.out，通过 Console 接口访问 UI 能力。

- 方便测试（可以用 MockConsole）
- 方便换 UI（终端 → Web → GUI）
- 命令只依赖接口，不依赖具体实现

## 第一步：Command — 命令定义

```
// cmd/Command.java
package com.rook.cmd;

public record Command(
    String name,              // 命令名，如 "/help"
    List<String> aliases,     // 别名，如 ["/?"]
    String description,       // 简短描述，用于 /help
    String usage,             // 用法说明，如 "/help [命令名]"
    CommandType type,         // 类型：LOCAL / UI_AFFECTING / PROMPT_FEED
    boolean hidden,           // 是否隐藏（不在 /help 显示）
    CommandHandler handler    // 执行逻辑
) {
    /**
     * 命令处理器
     * @param console 控制台接口，用于输出和 UI 操作
     * @param args 命令参数（去掉命令名后的部分）
     * @return null 表示纯输出；非 null 表示要注入到对话中触发 LLM
     */
    @FunctionalInterface
    public interface CommandHandler {
        String execute(Console console, String args);
    }

    /**
     * 便捷工厂方法：创建普通命令
     */
    public static Command of(
            String name, 
            String description, 
            CommandHandler handler) {
        return new Command(
            name, List.of(), description, "", 
            CommandType.LOCAL, false, handler
        );
    }

    /**
     * 便捷工厂方法：创建带别名的命令
     */
    public static Command of(
            String name, 
            List<String> aliases,
            String description, 
            CommandType type,
            CommandHandler handler) {
        return new Command(
            name, aliases, description, "", 
            type, false, handler
        );
    }
}
```

### 逐段详解

#### 1. 字段详解

|     字段      |            含义             |            示例            |
| :-----------: | :-------------------------: | :------------------------: |
|    `name`     |  主命令名，必须以 `/` 开头  |          `/help`           |
|   `aliases`   |   别名列表，也以 `/` 开头   |       `["/?", "/h"]`       |
| `description` |  简短描述，用于 /help 列表  |  "显示所有命令的帮助信息"  |
|    `usage`    | 详细用法，用于 /help <命令> |      "/help [命令名]"      |
|    `type`     |          命令类型           |           LOCAL            |
|   `hidden`    |          是否隐藏           |           false            |
|   `handler`   |          执行逻辑           | (console, args) -> { ... } |

#### 2. CommandHandler 接口

```
@FunctionalInterface
public interface CommandHandler {
    String execute(Console console, String args);
}
```

**函数式接口，可以用 Lambda 写：**

```
(console, args) -> {
    console.println("你好");
    return null;  // 纯输出
}
```

**返回值的含义：**

- `null`：纯输出，不影响对话
- 非 null：把这个字符串注入到对话中，触发 LLM

#### 3. 便捷工厂方法

```
public static Command of(String name, String description, CommandHandler handler) {
    return new Command(name, List.of(), description, "", CommandType.LOCAL, false, handler);
}
```

简单的命令不用写全 7 个参数，用 of 方法快速创建。

## 第二步：CommandType — 三种类型

```
// cmd/CommandType.java
package com.rook.cmd;

public enum CommandType {
    /**
     * 纯本地输出，不影响对话状态
     * 例如：/help, /status, /session
     */
    LOCAL,

    /**
     * 改变界面或程序状态
     * 例如：/exit, /clear, /plan
     */
    UI_AFFECTING,

    /**
     * 注入消息到对话中，触发 LLM 处理
     * 例如：/do, /review
     * 返回值就是要注入的消息文本
     */
    PROMPT_FEED
}
```

### 三种类型详解

#### LOCAL — 纯本地输出

**特点：**

- 只打印信息，不改变对话
- 不触发 LLM
- 返回 null

**示例：**

```
Command.of("/status", "显示系统状态", (console, args) -> {
    console.println("权限模式: " + permissionEngine.getMode());
    console.println("模型: " + currentModel);
    console.println("Token: " + tokenEstimator.estimate(history));
    return null;  // 纯输出
});
```

#### UI_AFFECTING — 改变界面 / 状态

**特点：**

- 改变程序状态或界面
- 不触发 LLM
- 返回 null

**示例：**

```
new Command(
    "/clear", List.of(), "清空对话和屏幕", "",
    CommandType.UI_AFFECTING, false,
    (console, args) -> {
        history.clear();
        console.clearScreen();
        return null;
    }
);
```

#### PROMPT_FEED — 注入消息触发 LLM

**特点：**

- 返回非 null 字符串
- 这个字符串会被当成用户消息注入到对话中
- 触发 LLM 处理

**示例：**

```
new Command(
    "/review", List.of(), "对当前修改进行代码审查", "",
    CommandType.PROMPT_FEED, false,
    (console, args) -> {
        // 返回要注入的提示词
        return "请对我刚才的代码修改进行全面的代码审查，"
            + "包括代码风格、潜在 bug、性能问题、安全问题。";
    }
);
```

**执行流程：**

1. 用户输入 `/review`
2. 命令执行，返回提示词字符串
3. Repl 把这个字符串当成用户消息
4. 触发 LLM 进行代码审查

**用户体验：** 就像用户手动输入了那段提示词一样。

### 为什么需要 Console 接口？

#### 1. 解耦

- 换 UI 实现？命令不用改
- 测试？用 MockConsole

#### 2. 统一输出风格

- 错误信息自动红色
- 成功信息自动绿色
- 不用每个命令都自己写 ANSI 转义码

#### 3. 方便测试

```

// cmd/impl/JLineConsole.java
package com.rook.cmd.impl;

import com.rook.cmd.Console;
import org.jline.reader.LineReader;
import org.jline.terminal.Terminal;

public class JLineConsole implements Console {

    private final Terminal terminal;
    private final LineReader reader;

    public JLineConsole(Terminal terminal, LineReader reader) {
        this.terminal = terminal;
        this.reader = reader;
    }

    @Override
    public void println(String text) {
        terminal.writer().println(text);
        terminal.writer().flush();
    }

    @Override
    public void print(String text) {
        terminal.writer().print(text);
        terminal.writer().flush();
    }

    @Override
    public void printError(String text) {
        println("\033[31m" + text + "\033[0m");  // 红色
    }

    @Override
    public void printSuccess(String text) {
        println("\033[32m" + text + "\033[0m");  // 绿色
    }

    @Override
    public void printWarning(String text) {
        println("\033[33m" + text + "\033[0m");  // 黄色
    }

    @Override
    public void clearScreen() {
        terminal.writer().print("\033[2J\033[H");  // 清屏 + 光标移到左上角
        terminal.writer().flush();
    }

    @Override
    public String readLine(String prompt) {
        return reader.readLine(prompt);
    }

    @Override
    public int readCharacter() {
        try {
            return reader.readCharacter();
        } catch (Exception e) {
            return -1;
        }
    }

    @Override
    public int getWidth() {
        return terminal.getWidth();
    }

    @Override
    public int getHeight() {
        return terminal.getHeight();
    }
}

## 第四步：CommandRegistry — 注册中心

```
// cmd/CommandRegistry.java
package com.rook.cmd;

import java.util.*;
import java.util.stream.Collectors;

public class CommandRegistry {

    // 主存储：命令名 → Command
    private final Map<String, Command> commands = new LinkedHashMap<>();
    
    // 别名映射：别名 → 主命令名
    private final Map<String, String> aliasMap = new HashMap<>();

    /**
     * 注册一个命令
     * 启动时检测冲突，有冲突直接抛异常
     */
    public void register(Command command) {
        // 检查主命令名冲突
        if (commands.containsKey(command.name())) {
            throw new IllegalArgumentException(
                "命令名冲突: " + command.name());
        }

        // 检查别名冲突
        for (String alias : command.aliases()) {
            if (commands.containsKey(alias) || aliasMap.containsKey(alias)) {
                throw new IllegalArgumentException(
                    "命令别名冲突: " + alias);
            }
        }

        // 注册
        commands.put(command.name(), command);
        for (String alias : command.aliases()) {
            aliasMap.put(alias, command.name());
        }
    }

    /**
     * 查找命令（支持别名）
     */
    public Optional<Command> find(String name) {
        // 先查主命令名
        if (commands.containsKey(name)) {
            return Optional.of(commands.get(name));
        }
        // 再查别名
        if (aliasMap.containsKey(name)) {
            return Optional.of(commands.get(aliasMap.get(name)));
        }
        return Optional.empty();
    }

    /**
     * 获取所有可见命令（用于 /help）
     */
    public List<Command> listVisible() {
        return commands.values().stream()
            .filter(cmd -> !cmd.hidden())
            .collect(Collectors.toList());
    }

    /**
     * 获取所有命令（包括隐藏的）
     */
    public List<Command> listAll() {
        return new ArrayList<>(commands.values());
    }

    /**
     * Tab 补全：根据前缀匹配命令
     */
    public List<String> complete(String prefix) {
        List<String> matches = new ArrayList<>();
        
        // 匹配主命令名
        for (String name : commands.keySet()) {
            if (name.startsWith(prefix)) {
                matches.add(name);
            }
        }
        
        // 匹配别名
        for (String alias : aliasMap.keySet()) {
            if (alias.startsWith(prefix)) {
                matches.add(alias);
            }
        }
        
        return matches;
    }

    /**
     * 命令数量
     */
    public int size() {
        return commands.size();
    }
}
```

#### 1. 注册 + 冲突检测

**为什么不在运行时才检测？**

- 启动时 fail fast，有问题马上发现
- 运行时才发现的话，用户可能已经用了很久，某个命令突然不能用
- 开发阶段就能发现冲突，不会带到生产

#### 2. 查找（支持别名）

先查主命令名，再查别名，都没有返回 empty。

#### 3. 可见 vs 全部

```

        .filter(cmd -> !cmd.hidden())
        .collect(Collectors.toList());

```

- `listVisible()`：用于 /help，不显示隐藏命令
- `listAll()`：用于调试，显示所有命令

**隐藏命令有什么用？**

- 内部调试命令，不想让普通用户看到
- 废弃命令，保留兼容但不推荐
- 开发中的命令

## 第五步：CommandDispatcher — 分发器

统一处理命令输入，解析、查找、执行。

```
// cmd/CommandDispatcher.java
package com.rook.cmd;

public class CommandDispatcher {

    private final CommandRegistry registry;

    public CommandDispatcher(CommandRegistry registry) {
        this.registry = registry;
    }

    /**
     * 分发执行命令
     * @param input 完整的输入行，如 "/help status"
     * @param console 控制台
     * @return PROMPT_FEED 命令返回注入文本；其他返回 null
     */
    public String dispatch(String input, Console console) {
        // 去掉首尾空白
        input = input.trim();
        if (input.isEmpty()) {
            return null;
        }

        // 分割命令名和参数
        String[] parts = input.split("\\s+", 2);
        String cmdName = parts[0];
        String args = parts.length > 1 ? parts[1] : "";

        // 查找命令
        Optional<Command> cmdOpt = registry.find(cmdName);
        if (cmdOpt.isEmpty()) {
            console.printError("未知命令: " + cmdName);
            console.println("输入 /help 查看所有命令");
            return null;
        }

        Command cmd = cmdOpt.get();

        try {
            // 执行命令
            String result = cmd.handler().execute(console, args);
            
            // PROMPT_FEED 类型返回非 null，注入到对话
            if (cmd.type() == CommandType.PROMPT_FEED && result != null) {
                return result;
            }
            
            return null;
        } catch (Exception e) {
            console.printError("命令执行失败: " + e.getMessage());
            e.printStackTrace();
            return null;
        }
    }
}
```

### 逐段详解

#### 1. 解析命令名和参数

```
String[] parts = input.split("\\s+", 2);
String cmdName = parts[0];
String args = parts.length > 1 ? parts[1] : "";
```

**`split("\\s+", 2)` 的含义：**

- `\\s+`：按一个或多个空白分割
- `2`：最多分割成 2 部分
- 这样参数部分可以包含空格

**示例：**

- `/help` → cmdName="/help", args=""
- `/help status` → cmdName="/help", args="status"
- `/echo hello world` → cmdName="/echo", args="hello world"

#### 2. 未知命令处理

```
if (cmdOpt.isEmpty()) {
    console.printError("未知命令: " + cmdName);
    console.println("输入 /help 查看所有命令");
    return null;
}
```

友好提示，告诉用户用 /help 查看所有命令。

#### 3. 执行 + 异常处理

```
try {
    String result = cmd.handler().execute(console, args);
    if (cmd.type() == CommandType.PROMPT_FEED && result != null) {
        return result;
    }
    return null;
} catch (Exception e) {
    console.printError("命令执行失败: " + e.getMessage());
    return null;
}
```

**异常处理：**

- 命令执行抛异常，不崩溃
- 打印错误信息，继续运行
- 单个命令的 bug 不影响整个程序

## 第六步：12 个内置命令

### 命令总览

|     命令      |     类型     |            作用            |
| :-----------: | :----------: | :------------------------: |
|    `/help`    |    LOCAL     |     显示所有命令的帮助     |
|    `/exit`    | UI_AFFECTING |          退出程序          |
|    `/plan`    | UI_AFFECTING |    进入计划模式（只读）    |
|     `/do`     | PROMPT_FEED  | 退出计划模式并注入执行提示 |
|  `/compact`   | UI_AFFECTING |     手动触发上下文压缩     |
|   `/clear`    | UI_AFFECTING |       清空对话和屏幕       |
|  `/session`   |    LOCAL     |      显示当前会话信息      |
|   `/memory`   |    LOCAL     |        列出记忆文件        |
| `/permission` |    LOCAL     |      显示当前权限模式      |
|   `/status`   |    LOCAL     |  显示系统状态（综合信息）  |
|   `/review`   | PROMPT_FEED  |        触发代码审查        |
|  `/worktree`  |    LOCAL     |     Git Worktree 管理      |

### 逐个详解

#### 1. /help — 显示帮助

```
new Command(
    "/help", List.of("/?"), 
    "显示所有命令的帮助信息",
    "/help [命令名]",
    CommandType.LOCAL, false,
    (console, args) -> {
        if (!args.isBlank()) {
            // 显示单个命令的详细帮助
            Optional<Command> cmd = registry.find(args.trim());
            if (cmd.isPresent()) {
                Command c = cmd.get();
                console.println("命令: " + c.name());
                console.println("描述: " + c.description());
                console.println("用法: " + c.usage());
                if (!c.aliases().isEmpty()) {
                    console.println("别名: " + String.join(", ", c.aliases()));
                }
            } else {
                console.printError("未知命令: " + args);
            }
        } else {
            // 显示所有命令列表
            console.println("可用命令：");
            console.println("");
            for (Command cmd : registry.listVisible()) {
                String line = String.format("  %-15s %s", 
                    cmd.name(), cmd.description());
                console.println(line);
            }
            console.println("");

## 第七步：Repl 集成 — 输入分流

```
// cli/Repl.java（片段）

public class Repl {

    private final CommandDispatcher dispatcher;
    private final Console console;
    private boolean running = true;

    public void start() {
        while (running) {
            String input = reader.readLine("> ");
            
            if (input == null) {
                break;  // Ctrl+D
            }
            
            input = input.trim();
            if (input.isEmpty()) {
                continue;
            }

            // ★ 输入分流
            if (input.startsWith("/")) {
                // 斜杠命令
                String feedText = dispatcher.dispatch(input, console);
                if (feedText != null) {
                    // PROMPT_FEED：注入消息触发 LLM
                    processMessage(feedText);
                }
            } else {
                // 普通文本 → AI 对话
                processMessage(input);
            }
        }
    }

    public void setRunning(boolean running) {
        this.running = running;
    }
}
```

### 输入分流逻辑

```
用户输入
    │
    ├─ 以 / 开头？
    │   ├─ 是 → 命令分发
    │   │   ├─ LOCAL → 纯输出，不触发 AI
    │   │   ├─ UI_AFFECTING → 改状态，不触发 AI
    │   │   └─ PROMPT_FEED → 返回文本，注入对话触发 AI
    │   └─ 否 → 普通对话 → 触发 AI
    │
    ▼
继续下一轮
```

// JLine3 补全器
Completer commandCompleter = (parser, line) -> {
    String buffer = line.line();
    
    // 只有以 / 开头才补全命令
    if (!buffer.startsWith("/")) {
        return;
    }
    
    // 获取前缀（最后一个空格之前的部分）
    String prefix = buffer.contains(" ") 
        ? buffer.substring(0, buffer.indexOf(' '))
        : buffer;
    
    // 从注册中心获取匹配
    List<String> matches = registry.complete(prefix);
    
    // 添加到补全候选
    for (String match : matches) {
        line.addCandidate(new Candidate(match + " "));
    }
};

// 注册补全器
reader.setCompleter(commandCompleter);

## 常见坑（详细版）

### 1. 别名冲突

**现象：** 启动时报错 "命令别名冲突"。

**原因：** 两个命令用了同一个别名，或者别名和另一个命令的主名一样。

**解决：**

- 启动时检测，直接抛异常（fail fast）
- 开发者马上就能发现，改一下别名
- 不让用户运行时才发现某个命令不能用

### 2. PROMPT_FEED 消息持久化

**现象：** `/review` 注入的提示词，下次恢复会话时还在。

**原因：** 注入的消息和真实用户消息一样，都被 save 到 session 了。

**这是正确的行为：**

- 用户应该知道 AI 为什么在做代码审查
- 恢复会话后，上下文完整
- 如果不想持久化，可以在消息上加个标记，存档时跳过

### 3. 命令名大小写

**现象：** `/Help` 和 `/help` 是两个命令。

**原因：** 我们的实现是大小写敏感的。

**解决：**

- 统一用小写
- 或者查找时转成小写（但要注意命令名存储也要小写）
- 大多数 CLI 工具都是大小写敏感的，保持一致就行

### 4. 参数解析太简单

**现象：** 带引号的参数解析不对，比如 `/echo "hello world"`。

**原因：** 我们用 `split("\\s+", 2)`，不处理引号。

**解决：**

- 简单命令够用了
- 复杂命令可以自己在 handler 里解析
- 或者用更完善的参数解析库（如 picocli）

### 5. 命令执行阻塞

**现象：** 某个命令执行很慢，界面卡住了。

**原因：** 命令在主线程同步执行。

**解决：**

- 简单命令同步执行没问题
- 慢命令（比如网络请求）可以在 handler 里异步执行
- 或者给命令加超时

### 6. 隐藏命令还能补全

**现象：** 隐藏命令不在 /help 里，但 Tab 补全能看到。

**原因：** complete () 方法用了 listAll，没过滤 hidden。

**解决：**

- complete () 也过滤 hidden 命令
- 或者隐藏命令也允许补全（方便调试），看需求

### 7. 命令太多，/help 太长

**现象：** 命令多了，/help 输出一屏装不下。

**解决：**

- 按类型分组显示
- 或者分页显示
- 或者只显示常用命令，加 `/help --all` 显示全部

### 8. 命令和普通对话混淆

**现象：** 用户想输入以 / 开头的普通文本，被当成命令了。

**原因：** 只要以 / 开头就当命令。

**解决：**

- 用 `//` 转义：`//这不是命令` → 当成普通文本
- 或者用引号包裹
- 大多数 CLI 工具都是这样，用户习惯就好

## 旧方式 vs 新方式对比

|   维度   |     switch-case（旧）      |     注册中心（新）      |
| :------: | :------------------------: | :---------------------: |
| 加新命令 | 改 switch、改 help、改补全 |    一行 register ()     |
|   别名   |    每个别名加一个 case     |      aliases 字段       |
|   补全   |        单独维护列表        |  自动从 registry 生成   |
|   帮助   |          手写文本          | 自动从 description 生成 |
| 冲突检测 |        运行时才发现        |       启动时检测        |
|   测试   |      难（依赖 Repl）       |   容易（MockConsole）   |
|  代码量  |       命令越多越膨胀       |   每个命令独立，清晰    |

**注册中心是 CLI 工具的标准做法，可维护性好很多。**
