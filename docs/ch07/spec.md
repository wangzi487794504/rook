# MewCode 第7章 - 上下文管理 Spec

## 背景

ch01-ch06 实现了对话、工具、Agent Loop、System Prompt、权限、MCP 六大能力。但消息历史无限增长，多轮 Agent Loop 轻松突破上下文窗口，当前全靠手动 :clear。

## 目标

- 两层压缩：轻量预防 + 重量兜底
- 单会话可工作数小时不因上下文溢出被拒
- 工具结果优先压缩，用户原文尽量保留
- 被替换的工具结果物理可访问，模型可显式重读
- 替换预览逐字节稳定，保持缓存命中
- 自动/手动压缩共用核心路径
- 摘要 LLM 禁工具、先草稿再正式
- 压缩后边界消息防脑补
- 3次失败熔断；撞墙紧急压缩+重试
- 窗口大小配置驱动；代码集中在 context/ 模块

## 功能需求

### 第一层：轻量预防 (F1-F4)
- F1: 工具结果 > 8KB → 存盘到 ~/.mewcode/context/，对话替换为预览+路径
- F2: 预览逐字节稳定，保证缓存命中
- F3: 多结果合计超阈值 → 从大到小依次存盘
- F4: 用户消息不截断不压缩

### 第二层：重量兜底 (F5-F10)
- F5: token 超 窗口-13K → 触发摘要
- F6: 尾部保留 ~10K token(至少5条)原文；更早消息生成结构化摘要
- F7: 摘要按六个固定部分组织
- F8: 摘要 Prompt 禁工具调，先草稿再正式
- F9: 压缩后插入边界消息
- F10: 摘要结果也走轻量预防

### Token 估算 (F11-F12)
- F11: 锚定最近 usage，新增消息按字符数/4 估算
- F12: 工具定义视为稳定内容，仅估算一次

### 紧急压缩 (F13-F14)
- F13: prompt_too_long → 紧急压缩 → 自动重试
- F14: 只重试一次

### 手动触发 (F15-F16)
- F15: :compress 命令，余量 3K
- F16: :compress status 查看使用率

### 熔断 (F17)
- F17: 连续 3 次摘要失败 → 熔断

### 跨 Provider (F18)
- F18: context_window 可配置，未配置时默认值

### 配置 (F19)
- F19: context_management: false 可关闭

## 非功能需求
- N1: 检查耗时 < 5ms
- N2: 存盘原子操作
- N3: 摘要失败降级不崩溃

## 不做的事
- 精确 tokenizer
- 摘要策略 ML 优化
- 多会话共享缓存
- 对话分支/回滚
