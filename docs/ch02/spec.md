# MewCode 第2章 - 工具系统 Spec

## 背景

第1章完成后，MewCode 是一个纯对话助手——用户输入，AI 回复。AI 无法读写文件、
无法执行命令、无法搜索代码。它是一个"聊天机器人"，不是"编程助手"。

本章的目标是为 MewCode 装上工具系统，让模型能够调用工具来完成实际操作。

## 目标

- 设计统一的 Tool 抽象接口，所有工具实现同一套契约
- 实现六个核心工具：读文件、写文件、改文件、执行命令、Glob 搜索、Grep 搜索
- 建立工具注册中心，集中登记、查找、输出为 API 格式
- LLM Provider 层支持流式解析工具调用（tool_use content block）
- 工具执行结果回灌进对话历史，模型据此给出最终回复
- 改文件走唯一匹配替换策略，匹配失败给出明确错误
- 本章只做单次工具调用（模型调一个工具→执行→回结果→模型回复），不循环

## 功能需求

### Tool 接口与注册
- F1: 提供统一的 `Tool` 接口，包含名称、描述、参数 JSON Schema、执行方法四个要素
- F2: 提供 `ToolRegistry` 注册中心，支持按名称查找工具，能输出为 API 所需的工具列表格式

### 六个核心工具
- F3: **读文件工具** — 接收文件路径，返回文件内容，支持指定行范围
- F4: **写文件工具** — 接收文件路径和内容，创建或覆盖写入文件
- F5: **改文件工具** — 接收文件路径、原文片段、替换文本，在文件中做唯一匹配替换；匹配0次或多次时报错
- F6: **执行命令工具** — 接收 shell 命令，在指定工作目录执行，返回 stdout/stderr/exitCode；带超时机制
- F7: **Glob 工具** — 接收目录路径和 glob 模式，返回匹配的文件路径列表
- F8: **Grep 工具** — 接收搜索文本和目录路径，返回匹配的文件路径和行内容

### Tool 执行
- F9: 每个工具执行带超时限制（可配置，默认30秒），超时后强制终止并返回超时错误
- F10: 工具执行异常时返回结构化的错误结果（包含错误码和消息），而非崩溃

### LLM 协议适配
- F11: AnthropicProvider 请求体中携带 `tools` 定义列表，模型可返回 `tool_use` content block
- F12: 流式 SSE 解析中能拼接不完整的 JSON 参数碎片，组装完整工具调用
- F13: 工具执行结果以 `tool_result` 消息回灌对话历史，再次调用 API 获取模型回复

### 交互流程
- F14: 用户在 REPL 发消息后，若模型返回 tool_use，自动执行工具，将结果回传并获取最终回复
- F15: 本章只执行单次工具调用：模型返回 tool_use → 执行 → 回传结果 → 获取回复 → 结束。不做循环

## 非功能需求

- N1: **执行超时** — 命令执行与潜在长耗时的工具受超时约束；超时即终止该工具并返回超时结果，界面不冻结、会话不挂死
- N2: **界面不阻塞** — 工具执行与流式期间界面保持响应（可滚动、可见进行中指示），不冻结
- N3: **跨协议一致体验** — 工具调用的触发、UI 展示、结果回灌、错误反馈，在 Anthropic 与 OpenAI 两种协议下行为一致
- N4: **健壮性** — 工具参数缺失/类型错误、路径非法、命令报错、JSON 参数解析失败等，均以结构化错误处理，绝不崩溃
- N5: **结果体量控制** — 大文件/长输出有上限或截断（读文件行数上限、命令输出截断、搜索结果条数上限），避免撑爆上下文
- N6: **密钥安全** — API 密钥不回显、不打印到对话区或任何输出中

## 不做的事（本章明确排除）

- 自动循环（Agent Loop）：模型拿到工具结果后如果还想调工具，本章不做，留到下一章
- 多工具并行调用：一次只执行一个工具
- 工具的权限控制/审批（用户确认弹窗）：后续章节加
- 工具执行日志/审计
- 自定义工具扩展机制（插件化）：本章六种工具写死在代码中
- 网络请求工具（如 WebFetch）

## 验收标准

### Tool 接口与注册
- AC1: 六个工具均已注册到 ToolRegistry，通过名称可查找到对应实例（验证：单元测试遍历六种名称）
- AC2: ToolRegistry 输出的工具列表 JSON 符合 Anthropic API 的 tool 定义格式

### 六个核心工具
- AC3: 读文件工具 — 指定存在的文件路径，返回文件内容；不存在的路径返回结构化错误
- AC4: 写文件工具 — 指定路径和内容，写入成功，再次读取内容一致
- AC5: 改文件工具 — 文件中有唯一匹配的原文片段，替换为新文本，再读取确认修改生效；0次匹配报"未找到匹配"；多次匹配报"匹配到N处"
- AC6: 命令执行 — 执行 `echo hello`，stdout 包含 "hello"，exitCode=0；执行超时命令，超时后返回超时错误
- AC7: Glob 工具 — 给定模式和目录，返回匹配的文件列表
- AC8: Grep 工具 — 给定搜索文本和目录，返回匹配的文件:行号:内容

### Tool 执行
- AC9: 工具执行超过30秒自动终止，返回"执行超时"
- AC10: 工具执行结果过大（超100KB）时自动截断，并附带截断提示

### LLM 协议适配
- AC11: AnthropicProvider 请求体包含 tools 定义，模型能返回 tool_use content block
- AC12: 流式 SSE 中 tool_use 的 JSON 参数碎片能被正确拼接还原
- AC13: 工具执行结果以 tool_result 回灌，二次调用 API 后获得模型的最终文本回复

### 交互流程
- AC14: REPL 中输入"帮我读一下 pom.xml 文件"，模型调用读文件工具，自动执行，回传结果，模型生成解读回复
- AC15: 输入真实请求后，仅有单次工具调用（不循环），模型拿到结果后给出最终文本回复
