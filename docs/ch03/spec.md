# MewCode 第3章 - Agent Loop Spec

## 背景

第2章完成后，MewCode 具备了六种工具能力，但交互模式是"一次工具调用即停止"：
用户发消息 → 模型调一个工具 → 执行 → 结果回灌 → 模型回复 → 结束。

如果任务需要多个步骤（如"找出所有过时的依赖，然后更新它们"），
模型无法继续——它拿到第一步结果后就被迫停下来了。

本章的目标是为 MewCode 装上 ReAct 自主循环，让模型在一个 Loop 中反复
"思考→调工具→看结果→再思考"，直到任务真正完成。

## 目标

- 实现 ReAct 模式的 Agent Loop：模型在一次用户请求中可连续调用多个工具
- Loop 有多种停止条件：模型完成、超过迭代上限、用户取消、连续错误等
- 用异步事件流解耦 Agent 核心逻辑与 CLI 界面
- 流式收集器做双路输出：实时推界面 + 攒完整回复
- 支持多工具并行调用，按副作用类型分批执行（只读并发，写入串行）
- Plan Mode 两段式：`/plan` 限只读工具出计划，`/do` 全工具执行

## 功能需求

### Agent Loop 核心
- F1: 实现 ReAct 循环引擎 —— 在单次用户请求内，反复执行「调 LLM → 解析响应 → 执行工具 → 回灌结果」直到满足停止条件
- F2: 六种停止条件：

| 停止条件 | 行为 |
|---------|------|
| 模型完成 | LLM 返回纯文本，不再调工具 → 正常结束 |
| 迭代上限 | 超过可配上限（默认 25）→ 停止并提示 |
| 用户取消 | 流式态 Esc/Ctrl+C → 停本轮，回空闲态，不退出程序；空闲态 Ctrl+C → 退出 |
| 未知工具 | 模型请求未注册工具 → 停止当前 Loop，提示 |
| 连续错误 | 同工具连续 3 次失败 → 停止并提示 |
| 流出错 | Provider 流返回错误 → 停本轮，提示，不崩溃不中断会话 |

### 异步事件流
- F3: 定义 AgentEvent 事件类型：`TEXT`、`TOOL_CALL`、`TOOL_RESULT`、`TOKEN_USAGE`、`PROGRESS`、`ERROR`、`DONE`
- F4: Agent Loop 通过事件管道（Producer/Consumer）推送事件，界面侧订阅消费，彻底解耦
- F5: 事件管道有界（1000 条），背压时阻塞推送，不丢事件

### 流式收集双路
- F6: `StreamCollector` 每轮请求双路输出：
  - **实时通道** — 每收到 token 立刻作为 TEXT 事件推送界面
  - **累积通道** — 拼接完整文本 + 拼接分片到达的 tool_use JSON 参数，供循环下一步判断

### 保序分批并发执行
- F7: 一次回复的多个工具调用按模型给出顺序扫描：
  - 连续的只读工具（read_file、glob、grep）→ 合并为同一并发批并行执行
  - 遇到有副作用工具（write_file、edit_file、exec_command）→ 单独串行执行
  - 保持整体相对顺序：批内并发完成，结果按原始调用顺序回灌
  - 每批最多 5 个只读并发，每个工具仍受 per-tool 超时约束

### 结果回灌与历史一致
- F8: 每轮的 assistant 回合（含工具调用）与工具结果回合按序写入对话历史
- F9: 下一轮请求携带完整历史（所有轮次 + 所有结果）
- F10: 任何提前终止（取消/上限/未知工具/出错）后，对话历史保持合法：
  - 工具调用与结果配对不破坏
  - 角色交替不破坏
  - 会话可继续对话
  - 取消时已发起但未完成的工具调用补「已取消」结构化结果

### Plan Mode 两段式
- F11: `:plan` 命令进入计划模式：
  - 只注入只读工具（read_file、glob、grep）到 LLM 请求
  - 附加计划态系统提示：要求模型先探索、出计划、不动手修改
- F12: `:do` 命令切回执行模式：
  - 恢复全工具注入
  - 自动发一条内置提示触发模型按上文计划执行
- F13: 模式跨轮保持，直到再次切换；Plan 阶段的对话历史保留到 Do 阶段

### Token 用量与进度
- F14: 从 Provider 流式响应的 `usage` 事件中提取每轮 token 用量（input/output），跨轮累加为会话累计量
- F15: 流式态期间实时展示当前迭代轮次（"第 3/25 轮"），让用户感知 Agent 在推进

### 跨协议一致
- F16: Anthropic 与 OpenAI 两协议均支持完整 Agent Loop——多轮工具调用、用量提取、取消行为一致

## 非功能需求

- N1: **循环不卡界面** — Agent Loop 在后台线程运行，CLI 保持响应，用户随时可取消
- N2: **迭代上限兜底** — 最大循环次数可配置（默认 25），防止死循环浪费 API 费用
- N3: **事件管道不丢不堵** — 有界队列（1000 条），超限时背压阻塞推送
- N4: **并行工具数量上限** — 单批只读并发最多 5 个，防线程爆炸
- N5: **历史一致性保障** — 任意中断后对话历史仍合法，不丢已完成的消息
- N6: **Plan/Do 模式隔离** — 切换模式仅影响 tools 列表，不重置会话状态

## 不做的事（本章明确排除）

- 权限审批系统（用户确认弹窗、工具白名单）
- 上下文自动压缩（历史过长时自动摘要/截断）
- 会话分支/回滚（undo 某次工具调用）
- 自定义 Agent Skill / 子 Agent
- 工具结果的富文本渲染
- MCP 协议集成

## 验收标准

### Agent Loop
- AC1: 发送一条需要两步工具的任务（如"帮我看 config.yaml 然后告诉我 provider 有几个"），模型两次调用 read_file 后再给出最终回复，不需要用户额外催促
- AC2: 超过迭代上限（设 3 轮）时自动停止并提示用户

### 用户取消
- AC3: 流式输出中按 Ctrl+C → 停止当前 Loop，回到 `> ` 提示符，程序不退出
- AC4: 空闲态按 Ctrl+C → 退出程序

### 事件流
- AC5: 单元测试验证 AgentEvent 各类型可被正确构建和消费
- AC6: 通过事件管道发送 10 个事件，消费者能完整按序收到

### 流式收集器
- AC7: StreamCollector 同时走实时通道（回调）和累积通道（StringBuilder），同一 token 两边都有
- AC8: tool_use 的 JSON 参数碎片能被正确拼接还原为完整参数

### 并行工具执行
- AC9: 三次只读工具（read_file ×2、glob ×1）在同一轮并发执行，wall-clock 明显小于串行总和
- AC10: 读+写混搭时，写排在读之后执行，整体顺序保持不变

### Plan Mode
- AC11: 输入 `:plan` 进入计划模式，发送"帮我修复 bug"，模型只用只读工具探索，不写不改
- AC12: 输入 `:do` 切回执行模式，模型能接着上文计划开始执行写入操作

### 历史一致性
- AC13: Loop 被 Ctrl+C 打断后，对话历史仍可继续用（工具调用和结果配对不坏）

### Token 用量
- AC14: 多轮对话后，TOKEN_USAGE 事件中的累计 input/output tokens 逐轮递增

### 跨协议
- AC15: 在 Anthropic 和 OpenAI 两种协议下分别跑 Agent Loop，行为一致
